# G28: 0.5 ns の切り取りでの混合の仕組みは、0.1 ns のときと同じか（資料Dの条件、水素結合の形成、1 ns先）

- 確かめること: G15 では 0.1 ns の切り取りで、単純な平均では回復率 0.435、差では 0.348 と弱く、2 つの推定値を別々の特徴量として入れたときだけ 0.756 になった。G24 では 0.5 ns の切り取りで混合が 1.015 まで上がった。0.5 ns でも同じ仕組みか。
- 状態: 完了。単純な平均は回復率 0.863、差は 0.673 で、どちらも混合（1.015）より 0.05 以上下回った。仕組みは 0.1 ns のときと同じで、2 つの推定値を別々に入れるところが効いている。

## 1. 何を確かめる実験か

条件は資料Dの水素結合の形成、1 ns先。0.5 ns の切り取り平均と第22案の生成平均について、単純な平均を 1 つの特徴量として入れた条件と、差（生成平均 − 切り取り平均）を 1 つの特徴量として入れた条件を測る。

読み方は先に固定した。単純な平均か差のどちらかが混合と同程度（差が 0.05 以内）なら、0.5 ns の切り取りでは混合の仕組みが変わったことになる。どちらも混合より 0.05 以上下回れば、仕組みは 0.1 ns のときと同じで、2 つの推定値を別々に入れるところが効いていることになる。

## 2. 条件

- 土台は資料Dの条件（水素結合の形成）と同じ。学習 1bgf_A・1ifg_A・1j8r_A・2b0a_A、テスト 1mix_A＋2qt4_A 合算、候補は学習 9,610件・テスト 4,972件、起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、予測幅 1 ns先、HistGradientBoosting（120回、学習率0.075、葉31、葉あたり最小15件、L2 0.02、種42）。
- K01 のキャッシュ（18軌道分の距離系列）を再利用した。新しい軌道の取得や生成器の読み込みはしていない。
- 生成平均の出所: K05 の `generated_series.npz`（第22案の5点系列）。生成5点 = [起点距離 d0（フレーム10、1 ns）、+0.1、+0.3、+0.5、+1.0 ns] の前方系列。対応付けのキーは（軌道ID、ドナー原子、アクセプター原子）。検証として、生成5点の最初の点と履歴の最終フレーム（起点距離）の最大誤差は、学習側 5.56e-07 Å、テスト側 6.08e-07 Å だった。
- 注意: 生成系列は起点から先への前方系列で、実履歴は起点までの後方系列。両者は起点距離 d0 を共有するが時間の向きが逆（K09 と同じ留保）。平均は向きに依らない量なので、この実験では向きの違いは平均の定義に影響しない（平均の列だけを使うため）。
- 条件: 静的のみ／履歴全部入り（参照）／切り取り平均だけ（0.5 ns）／生成平均だけ／混合（切り取り平均＋生成平均、2列）／単純な平均（(切り取り平均＋生成平均)/2、1列）／差（生成平均 − 切り取り平均、1列）。G15 は差を切り取り − 生成の向きで測ったが、符号を反転しても木の分割は同じため AUPRC は変わらない。
- 回復率 =（条件の AUPRC − 静的のみ）÷（実履歴の利得 +0.1178）。

## 3. 結果

### 土台の再現

1 ns先で静的のみ AUPRC 0.3637、全部入り 0.4815、利得 +0.1178 で、形成の記録と小数第4位まで完全一致した。切り取り平均だけは AUPRC 0.4544、回復率 0.770 で、G02 の値と一致した。混合は AUPRC 0.4833、回復率 1.015 で、G24 の値と一致した。

### 1 ns先の利得の回復率

| 条件 | AUPRC | AUC | Brier | Log Loss | 回復率 |
|---|---:|---:|---:|---:|---:|
| 静的のみ | 0.3637 | 0.9056 | 0.0432 | 0.1494 | 0.000 |
| 全部入り（実履歴） | 0.4815 | 0.9352 | 0.0395 | 0.1344 | 1.000 |
| 切り取り平均だけ（0.5 ns） | 0.4544 | 0.9311 | 0.0394 | 0.1344 | 0.770 |
| 生成平均だけ | 0.3746 | 0.9129 | 0.0430 | 0.1466 | 0.093 |
| 混合（2つの推定値を別々に） | 0.4833 | 0.9353 | 0.0387 | 0.1326 | 1.015 |
| 単純な平均 | 0.4653 | 0.9326 | 0.0387 | 0.1321 | 0.863 |
| 差 | 0.4429 | 0.9262 | 0.0403 | 0.1374 | 0.673 |

混合との差: 単純な平均は −0.152、差は −0.343。どちらも 0.05 を超えて下回った。

### 0.1 ns のときとの比較（G15）

| 条件 | 0.1 ns（G15） | 0.5 ns（この実験） |

| 混合 | 0.756 | 1.015 |

| 差 | 0.348 | 0.673 |

## 4. 読み取り

先に固定した読み方に照らすと、単純な平均も差も混合より 0.05 以上下回ったため、仕組みは 0.1 ns のときと同じで、2 つの推定値を別々に入れるところが効いている、というのがこの測定の結論。

ただし 0.1 ns のときと違う点もある。0.1 ns では単純な平均（0.435）と差（0.348）は切り取り平均だけ（0.570）をも下回ったが、0.5 ns では単純な平均（0.863）は切り取り平均だけ（0.770）を上回る。0.5 ns の切り取り平均は 0〜1 ns の平均との相関が 0.983 とすでに良い推定値で、生成平均との単純な平均は 2 つの推定値の誤差を打ち消し合う向きに働くため、1列でも混合の大部分（0.863）を拾える。とはいえ混合の 1.015 には 0.152 届かず、補正モデルが 2 つの推定値を別々に見て重み付けを変える余地が、残りの分にあたるとみるのが自然。

## 5. 判断できること・まだ分からないこと

- 判断できること: 0.5 ns の切り取りでも、混合の効き目は 2 つの推定値を別々に入れるところにある。単純な平均や差にまとめてしまうと、混合の回復率には届かない。仕組みは 0.1 ns のときと同じ。
- まだ分からないこと: 補正モデルが 2 つの推定値をどう組み合わせているか（重みの付け方や、起点距離などの条件による切り替え）。単純な平均が 0.5 ns では切り取り平均だけを上回る理由の直接の確かめ。
