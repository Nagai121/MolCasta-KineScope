# G04: 短い実MDの計算量は本当に安いか

- 確かめること: G02 で、0.1 ns の切り取りだけでも指導力の 0.570 が戻ると分かった。ただし G02 は実の履歴を切っただけで、短い実MDを実際に回す計算量は測っていない。この実験では、GROMACS で短い実MDを 0.1 ns と 1 ns で実際に回し、かかった実時間を測る。準備と平衡化の時間もあわせて測る。
- 状態: 中断（2026-11-24、統括の指示で Colab での GPU 版 GROMACS ビルドの再試行を止めた。GPU 版が作れないため、0.1 ns と 1 ns の実行はまだ測れていない）。

## 1. 何を確かめる実験か

資料Dのテストタンパク質のうち1つ（1mix_A、206残基）で、GROMACS による短い実MDを 0.1 ns と 1 ns で実行し、かかった実時間を測る。準備（トポロジー作成・箱・水・イオン・エネルギー最小化）と平衡化（NVT 100 ps・NPT 100 ps）にかかる時間もあわせて測り、0.1 ns の実行全体が 1 ns の実行全体の何分の1になるか出す。

読み方は先に固定した。0.1 ns の実行が 1 ns の実行の 3分の1 以下の時間で終われば、短い実MDの経路は計算量の面でも成り立つ。3分の1 を超えるようなら、固定の準備時間が大きく、短くするだけでは安くならない。その場合は、どこに時間がかかっているかも記録する。

## 2. 条件

- タンパク質: 1mix_A（PDB 1MIX の A鎖、206残基、重原子 1,680個）。出発構造は PDB の結晶構造。
- 力場: AMBER99SB-ILDN＋TIP3P（ATLAS は CHARMM36m だが、入れた GROMACS には CHARMM36 が付いておらず、計算量の測定には力場の違いはほぼ影響しないため）。
- 箱: 十二面体、タンパク質から 1.0 nm。水 17,630分子、NaCl 0.15 M（Na 53、Cl 58）で中和。全体で約 55,700原子。
- 段取り: pdb2gmx → editconf → solvate → genion → エネルギー最小化（最急降下法、最大 50,000歩）→ NVT 100 ps → NPT 100 ps → 本番 0.1 ns／1 ns。いずれも 2 fs刻み。
- 計算機: Colab の無料枠、T4 まで。GROMACS 2023.3 を CUDA 対応で作って使う。

## 実行の記録

- 仮想マシンでの試み: GROMACS 2023.3（Ubuntu のパッケージ、CPU のみ）を入れて系は組めた。準備の各段は合計 2.3 秒とごく短い。ただし MD が遅く、エネルギー最小化は 1 秒に 2 歩ほどで、766歩まで進んだところで仮想マシンの再起動で止まった。換算すると約 0.5 ns/日で、1 ns の実行に 2 日ほどかかるため、この仮想マシンでは測れないと判断し、Colab に移した。
- 1回目（`~/workspace/g04/colab_g04.log`、スクリプト `colab_g04.py`）: Colab には CUDA 13.0 しかなく、その nvcc が T4（sm_75）向けの計算を受け付けず、cmake の設定で止まった。
- 2回目（`~/workspace/g04/colab_g04b.log`、スクリプト `colab_g04b.py`）: conda-forge から cudatoolkit-dev=12.8 を試したが「存在しない」で止まった。この時点のスクリプトは 12.8 を固定していた。
- 3回目（`~/workspace/g04/colab_g04c.log`、スクリプト `colab_g04b.py` を直したもの）: 12.4 → 12.0 → 11.8 の順に試したが、いずれも conda-forge には存在せず、CUDA 12 の道具は入らなかった。
- 4回目（`~/workspace/g04/colab_g04d.log`、スクリプト `colab_g04b.py` を直したもの）: NVIDIA のチャンネルから cuda-nvcc=12.4・cuda-cudart-dev=12.4・cuda-cufft-dev=12.4 を試したが、cuda-cufft-dev=12.4 が存在せず止まった。予備の手として pip の nvidia-cuda-nvcc-cu12／nvidia-cuda-runtime-cu12／nvidia-cufft-cu12（いずれも 12.4.*）も試したが、nvidia-cufft-cu12==12.4.* に合う版が無く止まった。4回目のセッションは自分で終わったため、止める手当ては要らなかった。
- 版の食い違いについての確認（2026-11-24 統括からの指摘を受けて確かめた）: ログに出る 12.8 は2回目のもので、ディスク上のスクリプトの 12.4／12.0／11.8 は3回目のもの。別の試行の記録で、矛盾はない。
- 止めた理由（2026-11-24、統括の指示）: GPU 版 GROMACS のビルドが 4 回続けて止まったため、同じ路線の再試行はここで止めた。

## 再開する前に検討すること

- CPU 版での測定: この仮想マシンでは MD が約 0.5 ns/日と遅く、1 ns を直に回すのは無理。ただし短い区間だけ回して 1 歩あたりの時間を測り、準備＋平衡化＋本番の比率を計算で出す段取りなら、1 ns を回さずに答えを出せる。MD は 1 歩あたりの計算量がほぼ一定のため、この計算は筋が通る。短い区間の実測（エネルギー最小化の収束と 10 ps ほどの本番）だけはこの仮想マシンでもできる。
- 別の CUDA 12 の入れ方: CUDA 12.8 の runfile、apt の nvidia-cuda-toolkit-12-4、conda の cuda-nvcc だけを入れて cuFFT を別途用意する形など。4回目で試した NVIDIA チャンネルと pip では、cuFFT の 12.4 の部品が無かった。
- L4 での実行: L4（sm_89）なら CUDA 13 が使えるが、「Colab は無料枠、T4 まで」の指示を超えるため、使うなら指示の確認が要る。
- GROMACS 以外での測定（OpenMM など）: 指示が GROMACS のため、変えるなら確認が要る。
