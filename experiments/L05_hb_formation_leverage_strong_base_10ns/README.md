# L05: L02 の曲がりを予測幅 10 ns で測る（K06(b) の条件、水素結合の形成、10 ns先）

- 確かめる仮説: H6（運動の生成そのものの問題）に関わる、「短い実MDを安くする」経路の L 系列の続き。L02（強い土台、1 ns先）では、回復率は覆う長さに対して滑らかに上がり、L01（資料Dの条件）で見えた 0.6 ns の段は残らなかった。ここでは L02 と同じ方法・同じ土台で、予測幅だけを 10 ns に変えて同じ曲がりを測り、線（0.8 / 0.9）に届く長さと段の有無が予測幅でどう変わるかを見る。
- 状態: 完了。**10 ns先でも段はなかった。増え幅がいちばん大きいのは 1 ns先と同じく最初の 0→0.1 ns（全体 +0.234）で、0.5→0.6 ns の増え分（全体 +0.112）は 0.2→0.3 ns（+0.114）・0.3→0.4 ns（+0.106）と同程度にすぎない。** 回復率 0.8 に届く最小の長さは全体・平均とも 0.4 ns、0.9 に届く最小の長さは全体・平均とも 0.6 ns で、どちらも 1 ns先（0.7 ns / 0.8 ns）より短い側に寄った。ただし 10 ns先の曲がりは 1 ns先より単調ではなく、0.5 ns で一度下がる（全体 0.889 → 0.794）など小さい凹凸がある（区間は重なっており、ノイズの範囲）。

## 1. 何を確かめる実験か

実の 0〜1 ns の履歴を、始めの短い部分だけに切って使う。切り取りの長さを L01・L02 と同じ11通り（覆う長さ 0〜1.0 ns、0.1 ns 刻み）に変え、各長さで「切り取りの平均だけ」を履歴の特徴量として強い土台の補正モデルに入れたときの 10 ns先の利得の回復率を測る。あわせて、各長さの回復率にタンパク質単位の再標本化によるブートストラップ 95% 区間を付ける。

読み方は L02 と同じで、先に固定した。

1. 回復率 0.8 に届く最小の長さと、0.9 に届く最小の長さを、統合値（全体、pooled）で読む（タンパク質ごとの平均（macro）も併記する）。
2. 段の判定は、隣り合う長さの間の回復率の増え幅がいちばん大きい場所と、その大きさで読む。
3. 信頼区間はタンパク質単位のブートストラップ 10,000回（seed 42、パーセンタイル法）で付ける。各標本の中でも静的のみ・全部入り・各長さの AUPRC を測り直し、利得と回復率をその標本の中で計算し直す。
4. 段らしい場所があれば、その前後でタンパク質ごとの値も記録する。

## 2. 条件

- 土台は K06(b)（強い土台）と同じ。凍結した本体モデル T1I2006＋補正モデル HistGradientBoosting（160回、学習率 0.065、葉 15、葉あたり最小 20件、L2 0.15、種 20261121）。較正タンパク質 8つで学習し、未見の100タンパク質×3レプリカ（163,074行、10 ns先の陽性 12,714件）で評価する。静的特徴は5個、履歴の要約値は10個（最初、平均、標準偏差、最小、最大、最後−最初、最後−直前、3.5 Å以下割合、4.5 Å以下割合、増加割合）。
- 起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、ラベルは 10 ns先（ラベルの列の添字 2。予測幅の並びは [1, 5, 10, 30, 50, 90] ns）。条件ごとに学習し直す。
- 系列は G05 で作り直したもの（`~/workspace/kinescope/work/g05_series/`、タンパク質ごとの `r{r}_series`、11点×候補数）をそのまま使う。静的特徴と履歴の要約値は K06(b) の保存値（`~/workspace/k06b/run/k06b_out/`）を使う。実行はローカルVM（学習13条件で約30秒、ブートストラップ 10,000回で約16分。sklearn はスレッド数1、OMP_NUM_THREADS=1 など。1回目の実行は仮想マシンの再起動でブートストラップ 6000/10000 の時点で止まり、同じ条件で最初からやり直した。`run_l05.log` が1回目、`run_l05_rerun.log` がやり直しの記録）。

### 長さの呼び方（L01・L02 と同じ、結果を見る前に固定）

長さは「覆う長さ」で統一し、定義は L01・L02 にそのまま合わせた。軌道の保存間隔は 100 ps（0.1 ns）で、フレーム k は時刻 k×0.1 ns。覆う長さ L ns の切り取りはフレーム 0〜(L/0.1) を使う。

| 覆う長さ | フレーム | フレーム数 |
|---|---:|---:|
| 0 ns | 0 | 1 |
| 0.1 ns | 0, 1 | 2 |
| 0.2 ns | 0〜2 | 3 |
| 0.3 ns | 0〜3 | 4 |
| 0.4 ns | 0〜4 | 5 |
| 0.5 ns | 0〜5 | 6 |
| 0.6 ns | 0〜6 | 7 |
| 0.7 ns | 0〜7 | 8 |
| 0.8 ns | 0〜8 | 9 |
| 0.9 ns | 0〜9 | 10 |
| 1.0 ns | 0〜10 | 11 |

覆う長さ 0 ns はフレーム0だけ、つまり履歴の最初のフレームの距離そのもの（平均を取っても値は同じ）。起点フレーム10（1 ns）は変えず、ラベルは 10 ns先のまま。

G 系列の呼び方との対応は L02 と同じ。G145 の「1.0 ns」の切り取りはフレーム [0..9] で、L 系列の覆う長さ 1.0 ns（フレーム 0〜10、11フレーム全部の平均）とは違う。覆う長さ 1.0 ns は G81 の「全部の平均だけ（mean_only_full）」と同じ条件である。

| G 系列の名前 | フレーム | L01・L02・L05 の覆う長さ |
|---|---|---|
| G81 0.1 ns | 0, 1 | 0.1 ns |
| G81 0.5 ns | 0〜5 | 0.5 ns |
| G81 全部の平均だけ | 0〜10 | 1.0 ns |

### 条件の一覧（10 ns先）

- 静的のみ: 静的特徴5個だけ。
- 全部入り（full_history）: 静的特徴＋実履歴の要約値10個（0〜1 ns の11フレーム）。回復率の分母（実履歴の利得）の参照。
- 切り取りの平均だけ: 静的特徴＋切り取りの平均だけ。覆う長さ 0.0〜1.0 ns の11通り。

回復率 =（その長さの AUPRC − 静的のみ）÷（実履歴の利得）。全体（pooled）とタンパク質ごとの平均（macro）の両方で測る（G05・L02 と同じまとめ方）。macro の AUPRC は、陽性が0件でも全部でもないタンパク質（100タンパク質すべてが該当）ごとの AUPRC の平均。

## 3. ブートストラップの段取り（L02 と同じ、G147・G148・G162 と同じ）

- 回数: 10,000回。乱数 seed: 42。区間はパーセンタイル法（2.5%点と 97.5%点）。
- 再標本化の単位: タンパク質。テストの100タンパク質から復元抽出で100タンパク質を選び直す。
- 各ブートストラップ標本の中でも、静的のみ・全部入り・その長さの平均だけの AUPRC を測り直し、実履歴の利得と回復率をその標本の中で計算し直した。モデルは学習し直さず、学習済みのモデルの候補ごとの予測確率（`test_predictions.npz` に保存）を再標本化している。測っているのはテスト集合の取り方による揺れで、学習の揺れではない。
- 全体の AUPRC の計算は sklearn の average_precision_score と同じ段取りを numpy で書き直したものを使い、実際の予測確率で全条件について sklearn の値と 1e-9 未満まで一致することを確かめてから使った。タンパク質ごとの平均の標本内での値は、タンパク質ごとの AUPRC（学習済みモデルの予測から出した固定値）を、再標本化の重なり具合で重み付けして平均したもの。
- 10,000回の抽出すべてで、標本内の実履歴の利得は全体でもタンパク質ごとの平均でも 0 以下にならなかった（回復率が定義できない抽出は 0 件）。

### 先に固定した読み方への答え

1. **回復率 0.8 に届く最小の長さ: 覆う長さ 0.4 ns**（全体 0.889、タンパク質ごとの平均 0.885）。ただし単調ではなく、0.5 ns では全体 0.794 と線の下に戻る（平均では 0.827 と線の上）。0.4 ns と 0.5 ns の区間（全体で [+0.805, +0.982] と [+0.714, +0.883]）は大きく重なっており、この上下はノイズの範囲と見る。
2. **回復率 0.9 に届く最小の長さ: 覆う長さ 0.6 ns**（全体 0.906、タンパク質ごとの平均 0.907）。0.4 ns では全体 0.889 と線のすぐ下、0.5 ns では下がるため、初めて届くのは 0.6 ns。

## 5. 読み取り

- **10 ns先でも、回復率は短い切り取りで大きく戻り、特定の長さの段はない。** フレーム0だけで利得の 0.45、0.1 ns で 0.69 が戻り、増え分は最初の 0.1 ns（+0.234）に集中する。あとは +0.08〜+0.11 の増え分と小さい下がりが混ざりながら 0.9 ns の 1.097 まで上がる。
- 線に届く長さは 1 ns先より短い側に寄った（0.8 は 0.4 ns、0.9 は 0.6 ns）。予測幅が長いほうが、履歴の利得の割合は短い切り取りで戻りやすい。ただしこれは割合の話で、利得の絶対値は 10 ns先のほうが小さい（+0.0376）。
- 0.5 ns の下がり（全体 0.889 → 0.794）は、0.5 ns という長さに何かあるというより、区間が重なる範囲の揺れと見るのが妥当である。G81 でも 0.5 ns の回復率（全体 0.794）は今回と一致しており、学習し直しても同じ値になる条件だが、0.4 ns・0.6 ns との差は区間の中にある。
- 費用の側はまだ何も言えない。分母はシミュレーションの長さ（ns）で、実測の費用への換算は L03 の担当（L01・L02 の曲がりについて実施済み）。

## 6. 判断できること・まだ分からないこと

- 判断できること: 強い土台（未見100タンパク質×3レプリカ、水素結合の形成、10 ns先）では、回復率 0.8 に届く最小の覆う長さは 0.4 ns、0.9 に届く最小の覆う長さは 0.6 ns（どちらも全体・タンパク質ごとの平均で同じ）。増え幅がいちばん大きいのは 0→0.1 ns（全体 +0.234）で、段はない。1 ns先（L02）と比べると、線に届く長さは短い側に寄り、曲がりの単調さは弱い。
- まだ分からないこと: 他の予測幅（5・30・50・90 ns、L04・L06〜L08 の担当）でも線に届く長さが短い側に寄るか。0.5 ns の下がりのような凹凸が他の予測幅でも出るか。実測の費用に直したときの形。
