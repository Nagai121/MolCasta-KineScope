# L2-01: L02・L04〜L08 の曲がりを、区間を起点の直前に置き直して測り直す（水素結合の形成、平均だけ、強い土台）

- 確かめる仮説: L 系列の全面改訂（L2 系列）。L01〜L74 は履歴として先頭からの区間 [0..k] を起点フレーム10と組にしていたため、短い長さでは区間の終わりと起点の間に時間の空きがあった。E01 の測定で、この空きが回復率を水増ししていたことが分かった。ここでは区間を起点フレーム10の直前に置き直し（E01 の Protocol A と同じ置き方）、土台・候補・予測器の設定・読み方を対応する L 実験（L02・L04・L05・L06・L07・L08、水素結合の形成・平均だけ・強い土台）と完全に同じにして、6予測幅すべてで測り直す。
- 状態: 完了。**区間を起点の直前に置き直すと、短い側の回復率は L より下がり、0.8 の線に届く長さは 1 ns先を除く5予測幅で後ろにずれ、0.9 の線は 5 ns先（L2-01もLも届かず）を除く5予測幅で後ろにずれた。** ただし長さ 0（フレーム10だけ）の回復率は全予測幅でちょうど 0 で、L の長さ 0（フレーム0だけ）の 0.34〜0.69 は、静的な特徴にないフレーム0の距離の持ち込みだったと分かった。1 ns先だけは 0.8 の線に届く長さが L の 0.7 ns から 0.4 ns に短くなったが、0.9 の線は 0.8 ns から 1.0 ns に後ろにずれた。

## 1. 何を確かめる実験か

実の 0〜1 ns の履歴を、起点フレーム10の直前の短い区間だけに切って使う。区間の長さを L と同じ11通り（覆う長さ 0〜1.0 ns、0.1 ns 刻み）に変え、各長さで「区間の平均だけ」を履歴の特徴量として強い土台の補正モデルに入れたときの、6予測幅（1/5/10/30/50/90 ns先）それぞれの利得の回復率を測る。あわせて、各長さの回復率にタンパク質単位の再標本化によるブートストラップ 95% 区間を付ける。

読み方は L と同一で、先に固定した。

1. 回復率 0.8 に届く最小の長さと、0.9 に届く最小の長さを、統合値（全体、pooled）で読む（タンパク質ごとの平均（macro）も併記する）。
2. 段の判定は、隣り合う長さの間の回復率の増え幅がいちばん大きい場所と、その大きさで読む。
3. 信頼区間はタンパク質単位のブートストラップ 10,000回（seed 42、パーセンタイル法）で付ける。各標本の中でも静的のみ・全部入り・各長さの AUPRC を測り直し、利得と回復率をその標本の中で計算し直す。
4. 段の前後ではタンパク質ごとの値も記録する。

## 2. 条件

- 土台は K06(b)（強い土台）と同じ。凍結した本体モデル T1I2006＋補正モデル HistGradientBoosting（160回、学習率 0.065、葉 15、葉あたり最小 20件、L2 0.15、種 20261121）。較正タンパク質 8つで学習し、未見の100タンパク質×3レプリカ（163,074行）で評価する。静的特徴は5個（0: 凍結した本体の予測確率、1: 予測のもとの供与体・受容体間の距離、2: 供与体・受容体の残基の CA 間距離、3: 供与体が主鎖の N か側鎖か、4: 受容体が主鎖の O か側鎖か）、履歴の要約値は10個（最初、平均、標準偏差、最小、最大、最後−最初、最後−直前、3.5 Å以下割合、4.5 Å以下割合、増加割合）。
- 起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、条件ごとに学習し直す。
- 系列は G05 で作り直したもの（`~/workspace/kinescope/work/g05_series/`、タンパク質ごとの `r{r}_series`、11点×候補数）をそのまま使う。静的特徴と履歴の要約値は K06(b) の保存値（`~/workspace/k06b/run/k06b_out/`）を使う。
- 実行はローカルVM（sklearn はスレッド数1。学習は全予測幅で13条件×6予測幅＝78条件、約2分半。第1段階の前提確認込みで約157秒。ブートストラップ 10,000回は予測幅1つあたり約26〜31分、6予測幅で約2時間50分）。Colab は使っていない（割り当て文では Colab の CPU セッションを基本とされていたが、ローカルで回る軽さだったため）。

### 長さの呼び方（L と同じフレーム数、区間だけ起点の直前）

長さは「覆う長さ」で統一し、フレーム数は L01・L02 と同じ（覆う長さ L ns は L/0.1＋1 フレーム）。ただし区間は起点フレーム10の直前で、L の先頭からの区間 [0..(L/0.1)] とは置き方が違う。E01 の Protocol A と同じ置き方である。

### 条件の一覧（6予測幅すべて）

- 静的のみ: 静的特徴5個だけ。
- 全部入り（full_history）: 静的特徴＋実履歴の要約値10個（0〜1 ns の11フレーム）。回復率の分母（実履歴の利得）の参照。
- 区間の平均だけ: 静的特徴＋区間の平均だけ。覆う長さ 0.0〜1.0 ns の11通り。

回復率 =（その長さの AUPRC − 静的のみ）÷（実履歴の利得）。全体（pooled）とタンパク質ごとの平均（macro）の両方で測る（L02 と同じまとめ方）。macro の AUPRC は、陽性が0件でも全部でもないタンパク質ごとの AUPRC の平均。

## 3. ブートストラップの段取り（結果を見る前に固定、L02 と同じ）

- 回数: 10,000回。乱数 seed: 42。区間はパーセンタイル法（2.5%点と 97.5%点）。
- 再標本化の単位: タンパク質。テストの100タンパク質から復元抽出で100タンパク質を選び直す、ふつうのブートストラップである。
- 各ブートストラップ標本の中でも、静的のみ・全部入り・その長さの平均だけの AUPRC を測り直し、実履歴の利得と回復率をその標本の中で計算し直した。モデルは学習し直さず、学習済みのモデルの候補ごとの予測確率（`test_predictions.npz` に保存）を再標本化している。測っているのはテスト集合の取り方による揺れで、学習の揺れではない。
- 全体の AUPRC の計算は sklearn の average_precision_score と同じ段取り（しきい値で区切って精度と再現率を取り、再現率の増え分で重み付けする）を numpy で書き直したものを使い、実際の予測確率で全条件について sklearn の値と 1e-9 未満まで一致することを確かめてから使った。タンパク質ごとの平均の標本内での値は、タンパク質ごとの AUPRC（学習済みモデルの予測から出した固定値）を、再標本化の重なり具合で重み付けして平均したもの。
- 10,000回の抽出すべてで、標本内の実履歴の利得は全体でもタンパク質ごとの平均でも 0 以下にならなかった（回復率が定義できない抽出は 0 件）。

## 8. 読み取り

- **区間を起点の直前に置き直すと、短い側の回復率は L より下がった。** L の短い側の回復率のうち、フレーム0の距離の持ち込みにあたる分（長さ 0 で 0.34〜0.69、0.1 ns で 0.14〜0.54）が消え、0.8 の線に届く長さは 1 ns先を除いて後ろにずれ、0.9 の線は 5 ns先（どちらも届かず）を除いて後ろにずれた。E01 で示された「起点との間の時間の空きによる水増し」が、L の曲がりの短い側に確かに入っていた。
- **ただし 1 ns先では、0.8 の線に届く長さが 0.7 ns から 0.4 ns に短くなった。** 起点の直前の区間は、1 ns先の予測には L の先頭からの区間より効く。0→0.1 ns の増え分が +0.401 と L の +0.192 の2倍以上になったのも同じ向きである。予測幅が短いほど、起点に近い履歴の重みが大きい形である。
- **曲がりの形は、L と同じく滑らかで、突出した段はない。** 増え幅最大の区間は予測幅ごとに 0→0.1 ns・0.1→0.2 ns・0.2→0.3 ns に散らばり、1か所の跳ねで線をまたぐ形ではない。90 ns先の 0.2→0.3 ns の +0.410 は大きいが、0.2 ns の区間 [+0.160, +0.476] と 0.3 ns の区間 [+0.581, +0.916] は重なっておらず、タンパク質ごとでも中央値 +0.307 と広く見えるため、0.3 ns での上がりは実在する。ただし 0.8 の線に届く長さは 0.5 ns で、0.3 ns の上がりだけでは線に届かない。
- **長さ 0 の回復率が全予測幅でちょうど 0 になったのは、静的な特徴に起点の距離が含まれているためである。** フレーム10だけの平均は、静的な特徴の1番目と全く同じ値になるので、モデルは何も足されない。逆に L の長さ 0（フレーム0だけ）の 0.34〜0.69 は、静的な特徴にないフレーム0の距離が持ち込まれた分だったと分かった。
- 50 ns先は、0.8 の線に届くのが 1.0 ns と最も後ろで、0.9→1.0 ns の +0.130 でようやく両方の線を超える。0.8→0.9 ns はほぼ平ら（+0.001）で、50 ns先の曲がりは 0.9 ns まで上がりきらない形である。
- 5 ns先は 0.9 の線に L2 でも届かず（最大 0.895、L04 の最大 0.888 と同じ水準）。0.8 の線は 0.6 ns で届く。

## 9. 判断できること・まだ分からないこと

- 判断できること: 水素結合の形成・平均だけ・強い土台で、区間を起点の直前に置き直すと、0.8 に届く最小の長さは全体で 1 ns先 0.4 ns、5 ns先 0.6 ns、10 ns先 0.6 ns、30 ns先 0.7 ns、50 ns先 1.0 ns、90 ns先 0.5 ns。0.9 に届く最小の長さは全体で 1 ns先 1.0 ns、5 ns先 届かず、10 ns先 0.8 ns、30 ns先 0.7 ns、50 ns先 1.0 ns、90 ns先 0.8 ns。L と比べると、0.8 の線は 1 ns先を除いて後ろにずれ、0.9 の線は 5 ns先を除いて後ろにずれた。L の短い側の回復率には、フレーム0の距離の持ち込みによる水増しが入っていた。
- まだ分からないこと: 他の現象（水素結合の解離、塩橋、接触）でも同じ向きのずれが出るか。統計量6種の形でも同じか。90 ns先の 0.2→0.3 ns の +0.410 の上がりが何によるものかは、この実験では切り分けていない。実測の費用に直したときの形は、L03 の換算を L2 の曲がりに当て直す必要がある。

## 10. 実行の経緯

- 最初の実行は、19:43ごろの実行環境の再起動で 10 ns先のブートストラップが 8000/10000 のところで止まった。そのときのスクリプトは予測確率を最後にまとめて書く作りで、タンパク質ごとの予測はメモリ内にしかなく、失われた。残っていたのは前提確認の結果（6予測幅すべてで48項目が一致）と、ログに残った 1 ns・5 ns の要約だけだった。
- やり直しでは、計算の進め方を組み直した。第1段階で全予測幅の学習・予測を終えた時点で予測をファイル（`_checkpoint_phase1.npz`、58 MB）に保存し、予測幅ごとにブートストラップして断片（`_checkpoint_h{h}.json`）を保存する形にした。再起動で止まっても、終わった予測幅は飛ばして続きから再開できる。
- やり直しの第1段階では、チェックポイントの保存で不具合が出た。`np.savez` はファイル名の後ろに `.npz` を足すため、一時ファイル `_checkpoint_phase1.npz.tmp` が実際には `_checkpoint_phase1.npz.tmp.npz` としてできてしまい、`os.replace` が探す一時ファイルが見つからず FileNotFoundError で落ちた。直し方は、ファイルハンドルを開いて `np.savez_compressed` に渡す形に変え、指定したパスそのままに書かせるようにした（`run_l2_01_phase1.py` に直し方を注記として残した）。計算した予測そのものは一時ファイルに残っていたが、第1段階の計算し直しは約3分だったため、直したスクリプトで `run_all.sh` を最初から回し直した。
- やり直しの第1段階は約157秒で終わり、前提確認は6予測幅すべてで通った（差の最大は 0.0）。ブートストラップは予測幅1つあたり約26〜31分、6予測幅で約2時間50分かかった。途中で再起動は起きず、最後まで回った。
