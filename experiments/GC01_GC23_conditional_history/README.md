# KineScope 補佐実験 GC01・GC02

KineScope bd3bbee のG05は短い実履歴と強い土台の比較を登録済み。GCでは別の問いとして、凍結T1I2007と同程度の初期距離の候補に絞って、順位を変える情報を測った。新規MD、学習、モデル選定は行わない。

## 共通の手順

- InternalResearch 2f0f62c の選定済み静的前段と、ATLASの固定検証10配列、全3レプリカを使用。1 ns先の水素結合形成の距離代理ラベル。153,212候補、10,314正例。
- 同一タンパク質、起点距離0.1 Å幅、凍結スコア0.2ロジット幅で層を作成。各正例につき同じ層の負例を復元抽出で16個選ぶ。9,995正例、159,920比較、乱数種402。正例が上位なら1、同点は0.5。
- 対応差の区間はタンパク質単位の2,000回再標本化。検証パネル上の探索的比較で、多重比較の補正と独立テストは実施していない。マッチングは幅をもつため、距離とスコアの差は層内にも残る。
- ATLAS、MiniTopol、T1重みおよび前段重みのあるInternalResearch作業ディレクトリから python -m t2i.gc_assist を実行。元の候補には手を加えない。

## GC01 既存の静的前段の条件付き順位

凍結T1I2007の一致率51.75%。局所応答は51.87%、差+0.12ポイントで95%区間−0.32〜+0.53ポイント。全特徴併用は51.44%。既存の補正器で順位が改善することは確認できなかった。この結果から、静的前段の情報不足と補正器の読み出し不足は区別できない。

## GC02 実軌道100 ps後の変化を使う診断

実際の100 ps後の距離変化の負値で順位づけると59.43%。凍結スコアとの差+7.68ポイント、95%区間+6.38〜+9.04ポイント。各配列の方向は10配列すべてで正。100 ps後の観測を使うため、静的入力の本番予測とは別の診断。G05の実履歴入力や、補正による全候補AUPRCの向上率には直接換算できない。

再現モジュールは t2i/gc_temporal.py、gc_readout.py、gc_strata.py、gc_history.py、gc_sensitivity.py、gc_surrogate.py、gc_crossfit.py、gc_heterogeneity.py、gc_shuffle.py。GC12・13・14・16〜18は先にGC10・11を実行する。

### GC17〜23の追加結果

- GC17は10配列すべてで改善。500 ps履歴のプールAUPRC差のタンパク質対応95%区間は+0.01493〜+0.02703。検証内で選択した時間幅であり、区間は選択による楽観を補正しない。
- GC18は152,933候補の履歴を同程度の距離とスコアの別ペアに置換。AUPRCは本人履歴0.52016、10回の置換平均0.49426、凍結0.50003。粗い層内の条件差と分布のずれは残る。
- GC19は別レプリカでも同じ起点・同じ原子ペアが候補に入った67.52%の行に限定。原子インデックスの対応を配列で確認し、置換元の変位を対象側の起点距離に足した。同一行の凍結0.40576、本人履歴0.42858、別レプリカ0.40595。部分集合の基準を全候補と直接比較しない。
- GC20は候補独立のランダム欠損で、利用できる割合25/50/75%のAUPRCが0.50440/0.50919/0.51467。実際の欠損はランダムと限らない。
- GC21は既に観測した距離を丸める診断。0.2 Å刻み0.52007、0.4 Å刻み0.52010。0.8 Å刻みは0.51654、正確な閾値内割合だけ保持すると0.51918。丸めの格子と3.5 Åの相対位置に依存する。
- GC22は実履歴の点集合を保って順序のみ反転・ランダム化。AUPRCは原順序0.52016、反転0.52010、ランダム平均0.52023。この集計・補正器では時間順序の寄与が小さい。
- GC23は補正器を固定し、各入力欄をゼロに置換。閾値内割合だけゼロにすると0.51745、平均との差をゼロにすると0.51981、最小距離との差をゼロにすると0.52138。推論時の入力介入であり、各統計を削って再学習した場合の性能は未測定。

追加の再現モジュールは t2i/gc_replica.py、gc_budget.py、gc_order.py。GC19〜23はGC10の500 ps補正器を読み込む。

## アーカイブから再実行する場合

InternalResearch のコミット 2f0f62c の tseries-exploration-20261121 を作業ディレクトリにし、code/ の gc_*.py を既存の t2i/ にコピーする。MiniTopolのATLASワークスペースとT1重み・前段キャッシュを用意する。既存の t2i.frontends と t2i.frontdiagnostic を共通部品として利用する。results/ に実測JSONと補正用チェックポイントを収録した。
