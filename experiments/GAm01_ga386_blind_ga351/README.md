# GAm01 GA386 の GA351 盲採点（不足分の作り直しによる実行）

GAm は、Echizen の指示（2026-11-25）で始めた、どすこい側の GA 試行の系列です。Codex 側の不足分を待たず、こちらでできることを進めるためのものです。この GAm01 は、GA394 で止まっていた GA386 の GA351 盲採点を、不足分をこちらで作り直して実行したものです。

## 目的と条件（事前に固定）

- 対象は凍結済みの GA386（development.json の best = expanded-1.0-40/0.35、40 エポック、固定混合 35%）です。チェックポイント expanded-1.0-40.pt の SHA-256 は 1ed2a094cdd68fd58f2238082e1715c94aa8d7af1045d56107a8d75f9c5e4618 で、GA394 の記録と一致しました。読み込みは weights_only で行いました（NumPy の配列と dtype だけを許可リストに入れています）。
- パネルは GA351（予約 8 配列 5b1n_A、1utg_A、5h1n_B、1uha_A、1wq8_A、4f55_A、5dje_B、1vr8_A、起点 49、3,980 ペア）です。
- 採点経路は GA384 の盲採点（ga384_confirm.py の blind の進み方）と GA386 の確認（ga386_confirm.py の読み込み方）を組み合わせたもので、条件は変えていません。採点は 1 回だけです。
- 読み方（GA394 で固定）：親 GA348 と比べて相関が +0.005 以上上回り、RMSE が悪化していなければ「盲採点でも上積みが残った」。それ以外は数値をそのまま記録します。
- 健全性の確認を先に行いました。作り直した経路で親 GA348 のパネル値（相関 0.621945、RMSE 0.499672）が再現できなければ、GA386 の採点には進まず止めることにしていました。

## 作り直した部分と、元の経路との違い

GA394 の時点で不足していたのは、共有モジュールの frontends、gc_history、g2i_path35、explore と、予約 8 配列の実軌道でした。今回は次のように作り直しました。作り直したモジュールはこのディレクトリの rebuilt/ に置いてあります。

- 実軌道：tseries.data.acquire（GA351 の ga351_acquire.py と同じ手順）で ATLAS から取得しました。各配列 1001 フレーム × 3 レプリカで、GA351 の acquisition.json と一致しました。
- frontends（候補の組み立て）：ga333.candidates と ga365.parts（どちらも commit 済み）と同じ形で作り直しました。検証として、作り直した候補ペアは生成アンサンブルの保存ペアと 8 配列すべてで完全一致しました。
- frontends の第 3 の返り値（frozen の列）：元の frontends が返していた値で、静的な特徴量の組（compact）の 3 列目に入ります。学習時の中心が 0.0653（baselines.npz の real_baseline_center）なので 0 ではないことが分かり、blind-ga351.npz に保存された static の値から、baselines.npz のリッジを通して代数的に復元しました。復元した値は [0, 1] の範囲に収まる確率のような量で（平均 0.0726、標準偏差 0.1393、ちょうど 0 の値が多数）、他の列が元の経路と一致していることの裏づけにもなりました。復元した値は rebuilt/frozen_anchor.npz に保存してあります。
- gc_history（past）：GC ブランチに commit されていた同じ系統のコピーと同一のコードを使いました。
- explore（record）：JSON の書き出しだけを作り直しました。score はこの採点経路では使われないため、呼ばれたら止まる形にしてあります。
- g2i_path35（paths）：ga_static_offset の中で local と combined の特徴量にだけ使われます。採点経路が読むのは compact だけなので、この値は採点結果に影響しません。行数だけを合わせた空の配列を返す形にしました。
- ga_hybrid300（rod）：ga_native240 の読み込み時に名前だけが必要で、simulate は使わないため、呼ばれたら止まる形にしてあります。
- 使ったモジュールのコピー（Codex のもの、そのまま）：ga_static_offset（GA301 のアーカイブ版ソース）、ga_scale（GA303）、ga_force（GA304）、ga309（GA309）、ga314（GA314）、ga333（GA333）、ga344（GA344）、ga348（GA348）、ga_native_offset（GA305）、ga_native240（GA310）、ga_openmm_pilot（GA313）。tseries はこの仮想マシンの ~/workspace/k06b/pkg のものを使いました。
- モデル類はすべて commit 済みのものを使いました（ga318/all-8.ubj、ga330/all-9.ubj、ga347/all-9.ubj、ga344/generated-6.ubj、ga_native_offset/baselines.npz、ga_force/all-8.ubj）。

## 健全性の確認（採点の前に実施）

- 親 GA348：残差相関 0.6219451585202697（記録 0.6219451585202694、差は 3e-16）、RMSE 0.49967228165511945（記録と一致）、残差 SD 0.4994855302878378（一致）、バイアス −0.01365994463790095（一致）。static の配列は blind-ga351.npz と最大差 0.0 で完全一致しました。
- GA384 の再現：同じ経路で GA384（joint/False/30/0.2/False）を採点し直したところ、残差相関 0.6221390983455302（記録 0.6221390978666421）、RMSE 0.5005983154145225（記録 0.5005983155630238）で、ペアごとの混合予測も blind-ga351.npz の predicted と最大差 1.19e-07（float32 の精度の範囲）で一致しました。

どちらの確認も通ったので、GA386 の採点に進みました。

## 結果（GA386、GA351 パネル、3,980 ペア、1 回だけ採点）

| 対象 | 残差相関 | 残差 SD | RMSE | バイアス |
| --- | ---: | ---: | ---: | ---: |
| GA386（expanded-1.0-40/0.35） | 0.620304 | 0.499678 | 0.500066 | −0.019691 |
| 親 GA348 | 0.621945 | 0.499486 | 0.499672 | −0.013660 |
| GA384（再現値） | 0.622139 | 0.500145 | 0.500598 | −0.021301 |

親との差は相関で −0.001641、RMSE で +0.000394（悪化）です。事前に固定した読み方（相関 +0.005 以上かつ RMSE の悪化なし）には届かず、盲採点で GA386 の上積みは残りませんでした。数値はそのまま記録します。確認の線 0.700 に対しても、0.620 でまだ届いていません。

検証と予約のパネルで GA386 が示した上積み（検証の残差相関 0.615、前のパネル 0.694461、予約パネル 0.610223）は、この盲パネルでは親を上回る形では残らなかった、という結果です。
