# K05 生成軌道そのものの質の直接測定 ― 保存状況の確認と実軌道側の基準測定

- 確かめる仮説: H6（運動の生成そのものの問題）
- 状態: 生成軌道のデータが残っていないことを確認。実軌道側の基準値は測定済み。再生成の計画を本記録に固定した。

## 1. 生成軌道のデータは残っているか

参照元ブランチ `research/tseries-models-and-results-20261121`（MolCasta-InternalResearch）の全体（3,985ファイル）と、両リポジトリの Release を確認した。結論は、**候補ごとの生成軌道（座標の系列・距離の系列）はどこにも保存されていない**。

- 機構実験・スクリーン実験とも、生成結果はその場で8個の要約特徴に変換されて判別器に渡され、系列そのものは保存されていない（実装 `hb_learned_coordinate_paths.py` の `summarize`、`hb_trajectory_screen.py` の `summary` がメモリ上で変換する作り）。
- 機構実験のコードには、タンパク質ごとのキャッシュ（`hb-learned-coordinate-paths/*.npz`、局所サイト座標と弾性モード経路、教師つきのものは実MD変位も）を軌道の置き場に書く処理があるが、その置き場（元の実行機の `atlas-workspace/`）はリポジトリにもこの仮想マシンにもない。
- 生成軌道の実験は元の実行機で直接実行されたもので（機構実験の文書の再実行手順はローカル実行の形）、GitHub Actions の成果物にも生成系列はない。資料Dの Actions 成果物（run 44883044790）は結果の要約だけで、軌道ではない。

## 2. 実軌道側の基準測定（実施済み）

生成側と比較するための物差しとして、実軌道の距離系列の統計を先に測った。

- データ: この仮想マシンの変換済み実軌道18本（資料Dの6タンパク質×3レプリカ、各1,001フレーム、100 ps 間隔）。
- 候補: 起点（1 ns、フレーム10）で距離が 3.5〜6.0 Å のドナー・アクセプター重原子ペア（別残基どうし）。全18軌道で合計 14,582 件。1 ns 先の形成率は 5.34%。
- 系列: 起点までの履歴（0〜1 ns、11フレーム）、起点からの実継続（0〜1 ns、11フレーム）、実継続を生成側の教師時刻（0.1、0.3、0.5、1.0 ns）に間引いた5点系列の3種類。
- コード: `measure_real_baseline.py`（このディレクトリ）。結果: `real_baseline_results.json`（軌道ごとの値も収録）。

### 結果（18軌道をまとめた値）

| 量 | 履歴 0〜1 ns（11点） | 実継続 0〜1 ns（11点） | 実継続・間引き（5点） |
|---|---:|---:|---:|
| 距離の平均 (Å) | 5.078 | 5.089 | 5.069 |
| 距離の標準偏差 (Å) | 0.999 | 1.013 | 0.970 |
| ペアごとの標準偏差の平均 (Å) | 0.364 | 0.359 | 0.332 |
| ペアごとの変動幅（最大−最小）の平均 (Å) | 1.226 | 1.204 | 0.908 |
| 1ステップの変化の標準偏差 (Å) | 0.603 | 0.591 | 0.659 |
| 時間の自己相関（1つ遅れ、ペアごとの平均） | −0.021 | −0.022 | −0.172 |
| 3.5 Å 以下だったフレームの割合 | 5.06% | 4.89% | 4.24% |
| 一度でも 3.5 Å 以下になったペアの割合 | 16.1% | 15.3% | 11.6% |
| 境界をまたいだ回数（ペア平均） | 0.536 | 0.520 | 0.224 |
| 3.5 Å 以下にいた時間の長さ（フレーム数、該当ペアの平均） | 1.99 | 1.99 | 1.59 |

注意: 自己相関は系列が短い（11点・5点）と下向きの偏りが出る量で、白雑音でも11点では約 −0.1、5点では約 −0.25 が期待値になる。実測がそれより高い側にあることは、実系列に弱い正の時間相関があることと整合する。生成側との比較では、同じ点数・同じ計算方法でそろえる。

## 3. 再生成の計画（生成系列を作り直して測る）

対象は機構実験の第22案に絞る（K06 の記録のとおり、最良だったのはこの系統。スクリーン側の第22案は時刻が実時間に対応しないため、時間の自己相関の比較対象にならない）。

### 規模

- 資料Dの6タンパク質×3レプリカ、起点 1 ns の1フレーム、候補は第2節と同じ 14,582 件。これで実継続の間引き5点系列と1対1で比べられる。

### 手順

1. 起点フレーム（フレーム10）の構造と候補を、資料Dと同じ定義で作る（K06(a) の受け渡しコードと共通化する）。
2. 保存済みの生成器（`generator.pt`、SHA-256 は `generator.json` の記録と照合）を CPU で読み、候補ごとに弾性モードの初期推定＋学習した補正から、0.1、0.3、0.5、1.0 ns の4時点の局所座標経路を再構成する。第22案の経路は決定論的な1本なので、乱数の種によるばらつきはない。
3. 生成距離系列（起点＋4時点の5点）を候補ごとに保存する（npz 形式、14,582 件×5点で小さい。そのままこのリポジトリの実験ディレクトリに置ける大きさ）。
4. 第2節と同じ統計量を生成系列について計算し、実継続・間引き（5点）の列と並べて比べる。分布（平均・標準偏差・分位点）、ペアごとの標準偏差と変動幅、1ステップ変化の標準偏差、自己相関（5点同士で比較）、境界をまたぐ回数、3.5 Å 以下の割合と滞在の長さ、の全項目を同じ定義で出す。
5. あわせて、要約特徴の段階で情報がどれだけ落ちるかを見るため、生成系列から作った8特徴と、実系列（間引き前11点）から作った同じ8特徴の分布の違いも記録する（H5 との切り分けの材料）。

### 計算量の見込み

生成器の推論は CPU で候補1万件規模なら分単位（元の実験では第21〜25案全部の特徴生成が約33万行で57秒）。弾性モードの計算は軌道ごとに Cα の Hessian の固有分解（残基数150前後）で軽い。Colab は不要。

### 必要なもの

- 生成器のチェックポイントと生成コード一式: 参照元ブランチにある（K06 の記録に場所を明記）。
- 起点固定の受け渡しコード: 新規に書く（K06(a) と共通）。
- 実軌道データ: この仮想マシンにある18軌道で足りる。

## 4. 判断できること・まだ分からないこと

- 判断できること: 生成軌道そのものの質は、これまで一度も測られておらず、測るための保存データもない。質の議論は再生成から始める必要がある。実軌道側の物差しは本記録で固定できた。
- まだ分からないこと: 生成系列が実系列とどれだけ違うか（再生成後に初めて分かる）。違いが大きい場合に、それが判別器を通した改善のなさの主因かどうかは、K06 の再比較と合わせて判断する。
