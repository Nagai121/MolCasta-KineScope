# L2-14: 短いMDの長さに対して、指導力がどれだけ戻るか（区間を起点の直前に置き直した測り直し、K15の土台、塩橋の解離、統計量6種）

- 確かめる仮説: H6（運動の生成そのものの問題）に関わる L 系列の全面改訂（L2系列）の1件。L69〜L74（塩橋の解離、K15の土台、統計量6種、予測幅 1/5/10/30/50/90 ns先）と同じ土台・同じ読み方で、履歴の区間の置き方だけを変えて測り直す。平均だけの形も同じ実行で測り直し、統計量6種との比較に使う。
- 状態: 完了。前提確認（長さ 1.0 ns の点で L69〜L74 の記録と一致）は6つの予測幅すべてで通った。回復率 0.8／0.9 に届く最小の長さ（統合）は、1 ns先で 0.3 ns／0.3 ns（L では 0.3 ns／0.4 ns）、5 ns先で 0.8 ns／1.0 ns（L では 0.0 ns／0.0 ns）、10 ns先で 0.3 ns／1.0 ns（L では 0.1 ns／0.2 ns）、30 ns先で 0.8 ns／0.8 ns（L では 0.0 ns／0.0 ns）、50 ns先で 0.2 ns／0.4 ns（L では 0.6 ns／0.7 ns）、90 ns先で 0.1 ns／0.1 ns（L と同じ）で、予測幅によって伸び縮みが混ざった。長さ 0（フレーム10だけ）の回復率は全予測幅で 0 だった。塩橋の解離も、利得が小さい予測幅（30・90 ns先）では回復率の振れが大きい。

## 1. 何を確かめる実験か

L 系列では、履歴の区間を先頭からの区間（フレーム 0〜k）に取っていたため、短い長さでは区間の終わりと起点フレーム10の間に時間の空きがあった。E01 で、この空きが回復率を大きく見せていたことが分かった。L2系列では、区間を起点フレーム10の直前に置き直す（E01 の Protocol A と同じ置き方）。長さ L ns の区間はフレーム (10 − L/0.1)〜10 で、長さ 0 はフレーム10だけ、0.1 ns はフレーム 9〜10、1.0 ns はフレーム 0〜10（この点だけは L と同じ条件になる）。

各長さで、区間から計算した統計量6種（最初、平均、標準偏差、最小、最後−最初、4.0 Å以下割合。ここで「最初」は区間の最初のフレーム、「最後−最初」はフレーム10から区間の最初のフレームを引いたもの）を履歴の特徴量として K15 の土台のモデルに入れたときの利得の回復率を、予測幅 1/5/10/30/50/90 ns先で測る。回復率の分母は、L と同じく全部入り（静的特徴＋実履歴6統計量、フレーム 0〜10）の利得である。

前提確認（先に固定）: 長さ 1.0 ns の点は L と同じ条件になるので、静的のみ・全部入りの AUPRC が対応する L 実験（L69〜L74）の記録値と 5e-4 以内で一致すること、長さ 1.0 ns の平均だけの回復率（統合）が L69〜L74 で測り直された値と 5e-4 以内で一致すること、長さ 1.0 ns の統計量6種の回復率が 1.0 と 1e-6 以内で一致すること（全部入りと同一の特徴量になるため）を、6つの予測幅すべてで最初に確かめる。一致しなければ、その時点で止めて統括へ報告する。

読み方は L と同一に先に固定した。

1. 回復率 0.8 に届く最小の長さと、0.9 に届く最小の長さを、統合値で読む（タンパク質ごとの平均も併記）。
2. 隣り合う長さの間の回復率の増え幅がいちばん大きい場所と、その大きさで読む。
3. 信頼区間はタンパク質単位のブートストラップ 10,000回（種42、パーセンタイル法）で、統計量6種の曲がりについて計算する。
4. 増え幅が最大の場所では、その前後でタンパク質ごとの値も記録する（タンパク質ごとの回復率は全長さで記録する）。
5. あわせて、同じ実行で測り直した平均だけの曲がりと比べて、0.8 と 0.9 に必要な長さが縮んだかどうかを記録し、対応する L 実験の記録（最小の長さ・最大の増え幅・回復率の曲がり）と並べて記録する。

## 2. 条件

- 土台は K15 の条件（塩橋の解離）と同じ。学習58タンパク質・テスト30タンパク質（分け方は `experiments/K15_saltbridge_expansion/split.json` の orig＋additions）、候補は学習 735件・テスト 360件、起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、HistGradientBoosting（120回、学習率0.075、葉31、葉あたり最小15件、L2 0.02、種42）を条件ごとに学習し直す。塩橋の定義は L と同じ（境界 4.0 Å）。
- K53 のキャッシュ（`~/workspace/kinescope/work/k53_cache/`）を再利用する。
- 条件の一覧（予測幅ごと）: 静的のみ（静的特徴5個だけ）、全部入り（静的特徴＋実履歴6統計量、フレーム 0〜10。回復率の分母の参照）、区間の統計量6種（静的特徴＋区間の6統計量。長さ 0.0〜1.0 ns の11通り）、区間の平均だけ（静的特徴＋区間の距離の平均だけ。長さ 0.0〜1.0 ns の11通り）。
- 回復率 =（その長さの AUPRC − 静的のみ）÷（全部入りの利得）。統合値とタンパク質ごとの平均の両方で測る。タンパク質ごとの回復率は、そのタンパク質の全部入りの利得が正のときだけ定義し、それ以外は空欄（null）とする。
- 実行はローカルVM（L69 と同じ規模で、重い計算にはあたらないと判断した）。sklearn の学習はスレッド数を 1 に絞る。

## 4. 読み取り

- 長さ 0（フレーム10だけ）の回復率は、全予測幅で統合・平均とも 0 だった（L2-13 と同じ理由で、フレーム10だけの統計量は起点の距離で決まり、その距離は静的特徴にすでに入っている）。L では長さ 0（フレーム0だけ）の時点で回復率が 0.39〜1.11 あり、5・30 ns先ではその時点で線に届いていた。
- 線に届く長さの向きは予測幅で混ざった。5・10・30 ns先では L より大きく伸び（30 ns先では L の 0.0 ns に対して 0.8 ns）、1 ns先はほぼ同じ、50 ns先は統合では縮んだ（0.6／0.7 ns → 0.2／0.4 ns）がタンパク質ごとの平均では伸びていて読みが分かれた。90 ns先は L と同じ 0.1 ns で、起点の直前の 0.1 ns の時点で回復率が 1.2237 と全部入りの利得を超えた。ただし 90 ns先の利得は +0.0582 と小さく、信頼区間も [0.0930, 9.4834] と広いので、1 を超えた分の大きさは当てにならない。「0.1 ns で線に届く」という読みだけが確かである。
- 統計量6種と平均だけ（同じ実行）の比べでも短縮は一様ではない（5 ns先の 0.8 の線では平均だけのほうが短く、50 ns先では平均だけは線に届かなかった）。これは L69〜L74 と平均だけの比較で見られた形と同じである。
- 30 ns先は特に振れが大きい。利得が +0.0633 と小さいうえ、タンパク質ごとの平均では短い長さで回復率が大きな負の値になり（長さ 0.1 ns で −2.4926）、ブートストラップでも平均の 3,535回／10,000回で利得が正にならなかった。30 ns先の個別の数値は向きの参考にとどめる。

## 5. 読みの注意点

- テストは30タンパク質だが、タンパク質ごとに陽性が少ないため、回復率を定義できるのは予測幅ごとに 15〜18タンパク質だけである。統合値とタンパク質ごとの平均で読みが分かれる場所がある（50 ns先など）。
- 実測の費用への換算はしていない。分母はシミュレーションの長さ（ns）。
