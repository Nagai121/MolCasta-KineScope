# L45: 統計量6種で L09 の曲がりを強い土台で測る（K75 の条件、水素結合の解離、1 ns先）

- 状態: 完了。**統計量6種では、必要な長さは 0.1 ns 縮んだ。** 回復率 0.8 に届く最小の長さは 0.6 ns（平均だけでは 0.7 ns）、0.9 に届く最小の長さは全体・タンパク質ごとの平均とも 0.7 ns（平均だけでは全体 0.8 ns、平均 0.9 ns）で、形成の L39 と同じ縮み方である。同じ長さで比べると、差（6種 − 平均だけ）は 0 ns で 0.000、0.1 ns 以後はすべての長さで正で、最大は 0.7 ns の +0.097。増え幅がいちばん大きい場所は 0→0.1 ns（全体 +0.138）で、平均だけの場合（+0.099）より大きい。

## 1. 何を確かめる実験か

実の 0〜1 ns の履歴を、始めの短い部分だけに切って使う。切り取りの長さを L01・L02・L09 と同じ11通り（覆う長さ 0〜1.0 ns、0.1 ns 刻み）に変え、各長さで「切り取りの統計量6種」を履歴の特徴量として強い土台の補正モデルに入れたときの 1 ns先の利得の回復率を測る。あわせて、各長さの回復率にタンパク質単位の再標本化によるブートストラップ 95% 区間を付ける。比較のために、L09 とまったく同じ作り方の「切り取りの平均だけ」の条件も同じ実行で学習し直し、回復率を並べる。

読み方は先に固定した（L09・L39 と同じ）。

1. 回復率 0.8 に届く最小の長さと、0.9 に届く最小の長さを、統合値（全体、pooled）で読む（タンパク質ごとの平均（macro）も併記する）。L09（平均だけ）の答えと比べて、縮んだかどうかを明記する。
2. 段の判定は、隣り合う長さの間の回復率の増え幅がいちばん大きい場所と、その大きさで読む。
3. 信頼区間はタンパク質単位のブートストラップ 10,000回（seed 42、パーセンタイル法）で付ける。各標本の中でも静的のみ・全部入り・各長さの AUPRC を測り直し、利得と回復率をその標本の中で計算し直す。
4. 段の前後ではタンパク質ごとの値も記録する。

## 2. 条件

- 土台は水素結合の解離の強い土台（K75・K2-18 と同じ）。HistGradientBoosting の補正モデル（160回、学習率 0.065、葉 15、葉あたり最小 20件、L2 0.15、種 20261121）を較正タンパク質（6,144候補）で学習し、未見の100タンパク質×3レプリカ（76,342候補、1 ns先の陽性 12696件）で評価する。静的特徴は5個、履歴の要約値は10個。
- 入力は K2-18 の input_bundle.npz（静的特徴・履歴の要約値・11フレームの距離系列・ラベル）を使う。静的特徴と系列は K2-18 の系統（K75・K2-77・K2-84）と同じく float64 にそろえて使い、統計量6種のブロックだけは実験Dの作り方どおり float32 に落としてから並べた。
- 起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、ラベルは 1 ns先。条件ごとに学習し直す。
- 実行はこの仮想マシン（学習24条件とブートストラップ 10,000回）。途中結果を保存して再開できる形にした。

### 統計量6種の定義（実験Dの定義どおり、L39・L40 と同じ）

統計量6種は、実験D（固定した 1 ns 履歴の実験）の `features_from_history` の定義をそのまま使う。出典は MolCasta-InternalResearch ブランチ `research/fixed-1ns-3phen-6h-20261121` の `GPT遊び場/ATLAS-実軌道-2026-11-19/fixed_1ns_history_3phen_6h.py` で、並びは次の通り。

1. 最初の値（系列の最初のフレームの距離）
2. 平均
3. 標準偏差（ddof=0、numpy の `std` の既定）
4. 最小値
5. 最後−最初（系列の最後のフレーム − 最初のフレーム）
6. 閾値以下だった割合（閾値は水素結合の境界 3.5 Å。同スクリプトの `THRESH["hb"] = 3.5` で、割合は `(series <= bound).mean`）

値は float32 に落とす（同スクリプトの作り方どおり）。切り取りへの適用は、同じ式を切り取りの部分系列（フレーム 0〜k）にそのまま適用する。「最後」は切り取りの最後のフレーム、「割合」は切り取りの中での割合になる。覆う長さ 0 ns（1フレーム）では標準偏差と最後−最初は 0 になり、割合は「最初の値が 3.5 Å以下かどうか」の 0/1 になる。

### K75 の履歴特徴10個との関係

K75 の履歴特徴10個は、同じ11フレームから次の式で再現できる（下の premise で全数照合した）。

| 位置 | K75 の要約値10個 | 実験Dの6種に入るか |
|---:|---|---|
| 0 | 最初 | 入る（1番目） |
| 1 | 平均 | 入る（2番目） |
| 2 | 標準偏差 | 入る（3番目） |
| 3 | 最小 | 入る（4番目） |
| 4 | 最大 | 入らない |
| 5 | 最後−最初 | 入る（5番目） |
| 6 | 最後−直前 | 入らない |
| 7 | 3.5 Å以下割合 | 入る（6番目） |
| 8 | 4.5 Å以下割合 | 入らない |
| 9 | 増加割合（隣り合うフレームで増えた割合） | 入らない |

つまり実験Dの6種は K75 の10個の部分集合で、10個は6種に「最大、最後−直前、4.5 Å以下割合、増加割合」の4つを足した拡張である。したがって全部入り（11フレーム全部の要約値10個）は6種の上位集合で、覆う長さ 1.0 ns の6種の条件は、全部入りから4特徴を落とした条件にあたる。

### 長さの呼び方（L01・L02・L09 と同じ、結果を見る前に固定）

長さは「覆う長さ」で統一し、定義は L01・L02・L09 にそのまま合わせた。軌道の保存間隔は 100 ps（0.1 ns）で、フレーム k は時刻 k×0.1 ns。覆う長さ L ns の切り取りはフレーム 0〜(L/0.1) を使う（0 ns はフレーム0だけの1フレーム、1.0 ns はフレーム 0〜10 の11フレーム全部）。起点フレーム10（1 ns）は変えず、ラベルは 1 ns先のまま。G 系列の「1.0 ns」の切り取り（フレーム [0..9]）とは違う。

### 条件の一覧（1 ns先）

- 静的のみ: 静的特徴5個だけ。
- 全部入り（full_history）: 静的特徴＋実履歴の要約値10個（0〜1 ns の11フレーム）。回復率の分母（実履歴の利得）の参照。
- 切り取りの平均だけ: 静的特徴＋切り取りの平均だけ。覆う長さ 0.0〜1.0 ns の11通り。L09 とまったく同じ作り方（premise の照合と比較用）。
- 切り取りの統計量6種: 静的特徴＋切り取りの統計量6種。覆う長さ 0.0〜1.0 ns の11通り（主役）。

回復率 =（その長さの AUPRC − 静的のみ）÷（実履歴の利得）。全体（pooled）とタンパク質ごとの平均（macro、100タンパク質）の両方で測る（L09 と同じまとめ方）。K75 の記録との照合用に、タンパク質×レプリカ（300群）の平均も併せて出す。

## 3. ブートストラップの段取り（結果を見る前に固定、L09・L39 と同じ）

- 回数: 10,000回。乱数 seed: 42。区間はパーセンタイル法（2.5%点と 97.5%点）。
- 再標本化の単位: タンパク質。テストの100タンパク質から復元抽出で100タンパク質を選び直す。
- 各ブートストラップ標本の中でも、静的のみ・全部入り・各長さの AUPRC を測り直し、実履歴の利得と回復率をその標本の中で計算し直した。モデルは学習し直さず、学習済みのモデルの候補ごとの予測確率（`test_predictions.npz` に保存）を再標本化している。6種と平均だけの両方の系列を、同じ抽出で測っている。
- 全体の AUPRC の計算は L09 と同じ numpy 実装（sklearn の average_precision_score と同じ段取り）を使い、実際の予測確率で全24条件について sklearn の値と 1e-9 未満まで一致することを確かめてから使った。
- 10,000回の抽出すべてで、標本内の実履歴の利得は全体でもタンパク質ごとの平均でも 0 以下にならなかった（回復率が定義できない抽出は全体 0 件、平均 0 件）。

## 4. 結果

### 土台の再現（premise）

前提確認の all_ok は **false** である。落ちたのは外部記録との照合1件だけで、止める条件（定義の照合・土台の再現・平均だけの回復率の照合）はすべて通過したため、理由を明記して続けた（詳細は `premise_check.json`）。

1. **統計量の定義の照合**: 較正＋テストの全候補（82,486件）で、K2-18 の保存されている距離系列の11フレームから上の式で再計算した統計量6種が、保存されている履歴特徴10個の該当列（位置 [0, 1, 2, 3, 5, 7]）と最大差 1.43e-06 で一致した（float32 の丸めの範囲。基準は 1e-4 未満）。10個すべての列でも最大差は 1.43e-06 だった。
2. **土台の再現**: 1 ns先で静的のみ AUPRC は全体 0.5061、タンパク質ごとの平均 0.5222、タンパク質×レプリカの平均 0.5330。全部入りは全体 0.6142、タンパク質ごとの平均 0.6247、タンパク質×レプリカの平均 0.6345。利得は全体 +0.1081、タンパク質ごとの平均 +0.1025 で、L09 の記録と 5e-4 以内で一致した。
3. **平均だけの回復率の照合**: 同じ実行で学習し直した平均だけの条件の回復率は、全11長さ×全体・平均の22項目すべてが L09 の記録と 5e-3 以内で一致した（実際の差の最大は 0.0000）。
4. **外部記録との照合（不一致）**: 覆う長さ 1.0 ns の平均だけの回復率は全体 0.926 で、K2-18 の記録から計算した参照値 0.9343 とは 5e-3 以内で一致しなかった（差 0.0081）。続けた理由: このずれは L09 の premise でも同じ形で確認されたもので、K2-18 は Colab（sklearn 1.6.1）で測られた記録であり、同じ作り方でこの仮想マシンで測り直した記録（K2-77・K2-84）とは小数第4位まで一致したことから、土台の再現が崩れたのではなく参照の側のずれと判断した。今回も、同じ実行の平均だけの曲がりが L09 の記録と全長さで一致している（照合3）ことが、土台が保たれている直接の証拠になる。なお L09 では premise_check.json の all_ok が、この項目が落ちているのに true になっていた。今回は all_ok を全項目の結果どおり false と記録した。

## 5. 読み取り

- **必要な長さは 0.1 ns 縮んだ**（0.8 の線: 0.7→0.6 ns、0.9 の線: 全体 0.8→0.7 ns、平均 0.9→0.7 ns）。形成の 1 ns先（L39）と同じ縮み幅で、解離でも 1 ns先では平均以外の要約値が足しになる。
- 差は 0.1 ns 以後のすべての長さで正（+0.019〜+0.097）で、特に 0.6〜0.7 ns で大きい。L39 で見えた「0.1 ns で6種が平均だけを下回る」形は、解離の 1 ns先では出なかった（0.1 ns で +0.039）。
- 覆う長さ 0 ns（1フレーム）では回復率が平均だけと完全に一致した（0.443）。1フレームでは6種のうち実質効くのは「最初の値」と「3.5 Å以下だった割合」だけで、解離の 1 ns先では割合の二値情報は平均だけ（= 最初の値）から読みを変えなかった。
- 0.9 ns で回復率が 1.000 に届き、1.0 ns では 0.988。6種の条件が全部入り（要約値10個）の利得にほぼ並ぶ。
- 費用の側は L09 と同じくまだ何も言えない。分母はシミュレーションの長さ（ns）で、実測の費用への換算は L03 の形（G04 の実測との対応付け）で行う。

## 6. 判断できること・まだ分からないこと

- 判断できること: 強い土台（未見100タンパク質×3レプリカ、水素結合の解離、1 ns先）で履歴に統計量6種を使うと、回復率 0.8 に届く最小の覆う長さは 0.6 ns、0.9 に届く最小の覆う長さは全体で 0.7 ns（タンパク質ごとの平均では 0.7 ns）。平均だけ（L09）では 0.8 が 0.7 ns、0.9 が全体 0.8 ns（平均 0.9 ns）だった。増え幅がいちばん大きいのは 0.0→0.1 ns（全体 +0.138）。
- まだ分からないこと: 6種のうちどの要約値が押し上げ（または押し下げ）を担っているかは、この実験では切り分けていない。実測の費用に直したときの形（L03 の形の換算を解離にも当てるかどうか）。
