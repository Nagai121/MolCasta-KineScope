# L2-02: L09〜L14 の曲がりを、区間を起点の直前に置き直して測り直す（水素結合の解離、平均だけ、強い土台）

- 確かめる仮説: L 系列の全面改訂（L2 系列）。L01〜L74 は履歴として先頭からの区間 [0..k] を起点フレーム10と組にしていたため、短い長さでは区間の終わりと起点の間に時間の空きがあった。E01 の測定で、この空きが回復率を水増ししていたことが分かった。ここでは区間を起点フレーム10の直前に置き直し（E01 の Protocol A と同じ置き方）、土台・候補・予測器の設定・読み方を対応する L 実験（L09・L10・L11・L12・L13・L14、水素結合の解離・平均だけ・強い土台）と完全に同じにして、6予測幅すべてで測り直す。
- 状態: 完了。**区間を起点の直前に置き直すと、短い側の回復率は L より下がり、0.8 の線に届く長さは 1 ns先を除く5予測幅で後ろにずれ、0.9 の線も 1 ns先（全体）と 5 ns先（全体・平均とも同じ）を除く予測幅で後ろにずれた。** 長さ 0（フレーム10だけ）の回復率は全予測幅でちょうど 0 で、L の長さ 0（フレーム0だけ）の 0.44〜0.64 は、静的な特徴にないフレーム0の距離の持ち込みだったと分かった。形成の L2-01 では 1 ns先の 0.8 の線が短くなったのに対し、解離では 1 ns先も 0.8 の線が 0.7 ns から 0.5 ns に短くなった。増え幅最大の区間は6予測幅すべてで 0→0.1 ns になった。

## 1. 何を確かめる実験か

実の 0〜1 ns の履歴を、起点フレーム10の直前の短い区間だけに切って使う。区間の長さを L と同じ11通り（覆う長さ 0〜1.0 ns、0.1 ns 刻み）に変え、各長さで「区間の平均だけ」を履歴の特徴量として強い土台の補正モデルに入れたときの、6予測幅（1/5/10/30/50/90 ns先）それぞれの利得の回復率を測る。あわせて、各長さの回復率にタンパク質単位の再標本化によるブートストラップ 95% 区間を付ける。

読み方は L と同一で、先に固定した。

1. 回復率 0.8 に届く最小の長さと、0.9 に届く最小の長さを、統合値（全体、pooled）で読む（タンパク質ごとの平均（macro）も併記する）。
2. 段の判定は、隣り合う長さの間の回復率の増え幅がいちばん大きい場所と、その大きさで読む。
3. 信頼区間はタンパク質単位のブートストラップ 10,000回（seed 42、パーセンタイル法）で付ける。各標本の中でも静的のみ・全部入り・各長さの AUPRC を測り直し、利得と回復率をその標本の中で計算し直す。
4. 段の前後ではタンパク質ごとの値も記録する。

## 2. 条件

- 土台は K75（水素結合の解離の強い土台）と同じ。補正モデル HistGradientBoosting（160回、学習率 0.065、葉 15、葉あたり最小 20件、L2 0.15、種 20261121）。較正タンパク質 8つ（6,144件）で学習し、未見の100タンパク質×3レプリカ（76,342行）で評価する。静的特徴は5個（0: 凍結した本体の予測確率、1: 予測のもとの供与体・受容体間の距離、2: 供与体・受容体の残基の CA 間距離、3: 供与体が主鎖の N か側鎖か、4: 受容体が主鎖の O か側鎖か）、履歴の要約値は10個（最初、平均、標準偏差、最小、最大、最後−最初、最後−直前、3.5 Å以下割合、4.5 Å以下割合、増加割合）。
- 入力は K2-18 の `input_bundle.npz`（静的特徴5個、履歴の要約値10個、11フレームの距離系列、ラベル6列）をそのまま使う。L2-01（形成）が K06(b) の保存値と G05 の系列を使ったのに対し、解離は K75・K2-77・K2-84 の系統と同じくこのバンドルを使う。
- 特徴量は K2-18 の系統と同じく float64 にそろえて sklearn に渡す。float32 のままだと 90 ns先の全部の平均だけの条件で分割が変わり、AUPRC が 0.0018 ずれることが L09 で確認されている。
- 解離の定義は L09〜L14 と同じ（K2-18 のバンドルの定義どおり。起点の供与体・受容体間の距離が 3.5 Å 以下で、ラベルは予測幅の先の距離が 3.5 Å を超えること）。
- 起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、条件ごとに学習し直す。
- 実行はローカルVM（sklearn はスレッド数1。学習は全予測幅で13条件×6予測幅＝78条件。第1段階の前提確認込みで約111秒。ブートストラップ 10,000回は予測幅1つあたり約5分、6予測幅で約30分、全体で約32分）。Colab は使っていない（割り当て文では Colab の CPU セッションを基本とされていたが、ローカルで回る軽さだったため。L2-01 と同じ判断）。

### 長さの呼び方（L と同じフレーム数、区間だけ起点の直前）

長さは「覆う長さ」で統一し、フレーム数は L01・L02 と同じ（覆う長さ L ns は L/0.1＋1 フレーム）。ただし区間は起点フレーム10の直前で、L の先頭からの区間 [0..(L/0.1)] とは置き方が違う。E01 の Protocol A と同じ置き方である。

|---|---|---|
| 0 ns | 10 | 1 |
| 0.1 ns | 9, 10 | 2 |
| 0.2 ns | 8〜10 | 3 |
| 0.3 ns | 7〜10 | 4 |
| 0.4 ns | 6〜10 | 5 |
| 0.5 ns | 5〜10 | 6 |
| 0.6 ns | 4〜10 | 7 |
| 0.7 ns | 3〜10 | 8 |
| 0.8 ns | 2〜10 | 9 |
| 0.9 ns | 1〜10 | 10 |
| 1.0 ns | 0〜10 | 11 |

覆う長さ 0 ns はフレーム10だけ、つまり起点の距離そのもの（平均を取っても値は同じ）。覆う長さ 1.0 ns はフレーム 0〜10 の11フレーム全部で、L の同じ長さと同一条件になる（前提確認の点）。

### 条件の一覧（6予測幅すべて）

- 静的のみ: 静的特徴5個だけ。
- 全部入り（full_history）: 静的特徴＋実履歴の要約値10個（0〜1 ns の11フレーム）。回復率の分母（実履歴の利得）の参照。
- 区間の平均だけ: 静的特徴＋区間の平均だけ。覆う長さ 0.0〜1.0 ns の11通り。

回復率 =（その長さの AUPRC − 静的のみ）÷（実履歴の利得）。全体（pooled）とタンパク質ごとの平均（macro）の両方で測る（L09 と同じまとめ方）。macro の AUPRC は、陽性が0件でも全部でもないタンパク質ごとの AUPRC の平均。

## 3. ブートストラップの段取り（結果を見る前に固定、L09 と同じ）

- 回数: 10,000回。乱数 seed: 42。区間はパーセンタイル法（2.5%点と 97.5%点）。
- 再標本化の単位: タンパク質。テストの100タンパク質から復元抽出で100タンパク質を選び直す、ふつうのブートストラップである。
- 各ブートストラップ標本の中でも、静的のみ・全部入り・その長さの平均だけの AUPRC を測り直し、実履歴の利得と回復率をその標本の中で計算し直した。モデルは学習し直さず、学習済みのモデルの候補ごとの予測確率（`test_predictions.npz` に保存）を再標本化している。測っているのはテスト集合の取り方による揺れで、学習の揺れではない。
- 全体の AUPRC の計算は sklearn の average_precision_score と同じ段取り（しきい値で区切って精度と再現率を取り、再現率の増え分で重み付けする）を numpy で書き直したものを使い、実際の予測確率で全条件について sklearn の値と 1e-9 未満まで一致することを確かめてから使った。タンパク質ごとの平均の標本内での値は、タンパク質ごとの AUPRC（学習済みモデルの予測から出した固定値）を、再標本化の重なり具合で重み付けして平均したもの。
- 10,000回の抽出すべてで、標本内の実履歴の利得は全体でもタンパク質ごとの平均でも 0 以下にならなかった（回復率が定義できない抽出は 0 件）。

## 4. 前提確認（長さ 1.0 ns の点で L と一致すること）

長さ 1.0 ns の点は区間が [0..10] になり L と同一条件になるため、静的のみ・全部入りの AUPRC と利得、および 1.0 ns の点の回復率が、対応する L 実験の記録値と一致することを、6予測幅すべてについて最初に確かめた。照合は48項目（予測幅6 × 静的のみ全体・平均、全部入り全体・平均、利得全体・平均、回復率 1.0 ns 全体・平均）で、**すべて一致し、差の最大は 0.0 だった**（`premise_check.json`）。土台の再現に問題はない。

## 8. 読み取り

- **区間を起点の直前に置き直すと、短い側の回復率は L より下がった。** L の短い側の回復率のうち、フレーム0の距離の持ち込みにあたる分（長さ 0 で 0.44〜0.64、0.1 ns で 0.03〜0.44）が消え、0.8 の線に届く長さは 1・5 ns先を除いて後ろにずれ、0.9 の線は 5 ns先を除いて後ろにずれた。E01 で示された「起点との間の時間の空きによる水増し」が、L の曲がりの短い側に確かに入っていた。
- **ただし 1 ns先と 5 ns先では、0.8 の線に届く長さが短くなった。** 1 ns先は 0.7 ns から 0.5 ns、5 ns先は全体の読みで 0.5 ns から 0.4 ns に短くなった。起点の直前の区間は、短い予測幅の予測には L の先頭からの区間より効く。0→0.1 ns の増え分が 1 ns先で +0.508、5 ns先で +0.394 と L の最大の数倍になったのも同じ向きである。予測幅が短いほど、起点に近い履歴の重みが大きい形である。
- **増え幅最大の区間が6予測幅すべてで 0→0.1 ns になった。** 形成の L2-01 では最大の区間が 0→0.1 ns・0.1→0.2 ns・0.2→0.3 ns に散らばったのと対照的で、解離では起点の直前の最初の 0.1 ns が、どの予測幅でも突出して効く。タンパク質ごとの増え分の中央値も +0.307〜+0.487 と広く見え、0.1 ns での上がりは実在する。ただし 0.1 ns だけではどの予測幅でも 0.8 の線には届かず、曲がりはその後もなだらかに上がる形で、1か所の跳ねで線をまたぐ形ではない。
- **長さ 0 の回復率が全予測幅でちょうど 0 になったのは、静的な特徴に起点の距離が含まれているためである。** フレーム10だけの平均は、静的な特徴の1番目と全く同じ値になるので、モデルは何も足されない。逆に L の長さ 0（フレーム0だけ）の 0.44〜0.64 は、静的な特徴にないフレーム0の距離が持ち込まれた分だったと分かった。
- 10 ns先は 0.5 ns 以後、回復率が 1 を超える（全部の平均だけが全部入りを上回る）。L11 と同じ形で、区間の置き方を変えても残った。
- 30 ns先と 50 ns先と 90 ns先は、0.8 の線に届く長さが L より 0.2〜0.4 ns 後ろにずれ、0.9 の線も 0.3〜0.4 ns 後ろにずれた。長い予測幅ほど、L の短い側の水増しが大きかった。

## 9. 判断できること・まだ分からないこと

- 判断できること: 水素結合の解離・平均だけ・強い土台で、区間を起点の直前に置き直すと、0.8 に届く最小の長さは全体で 1 ns先 0.5 ns、5 ns先 0.4 ns、10 ns先 0.5 ns、30 ns先 0.7 ns、50 ns先 0.7 ns、90 ns先 0.6 ns。0.9 に届く最小の長さは全体で 1 ns先 0.9 ns、5 ns先 0.7 ns、10 ns先 0.6 ns、30 ns先 0.9 ns、50 ns先 0.8 ns、90 ns先 1.0 ns。L と比べると、0.8 の線は 1・5 ns先で短くなり、他の4予測幅で後ろにずれた。0.9 の線は 5 ns先を除いて後ろにずれた。L の短い側の回復率には、フレーム0の距離の持ち込みによる水増しが入っていた。
- まだ分からないこと: 他の現象（塩橋、接触）でも同じ向きのずれが出るか。統計量6種の形でも同じか。実測の費用に直したときの形は、L03 の換算を L2 の曲がりに当て直す必要がある。

## 10. 実行の経緯

- 実行は一度で最後まで回った。途中で再起動は起きず、止まり直しはなかった。第1段階（全予測幅の学習・予測と前提確認）は約111秒、ブートストラップは予測幅1つあたり約5分（295〜302秒）、6予測幅で約30分、全体で約32分だった。
- L2-01 の教訓をそのまま使った。第1段階で全予測幅の学習・予測を終えた時点で予測をファイル（`_checkpoint_phase1.npz`、約33 MB）に保存し、予測幅ごとにブートストラップして断片（`_checkpoint_h{h}.json`）を保存する形にした。再起動で止まっても、終わった予測幅は飛ばして続きから再開できる。
- チェックポイントの保存では、`np.savez` がファイル名の後ろに `.npz` を足す不具合に注意し、L2-01 と同じくファイルハンドルを開いて `np.savez_compressed` に渡す形にした（`run_l2_02_phase1.py` に直し方を注記として残した）。
