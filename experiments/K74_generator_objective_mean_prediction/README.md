# K74 生成器の補正を、ペアの平均距離を直接当てる目的で学習し直すと誤差は減るか（資料Dの条件、水素結合）

## 問い

これまで生成器は座標の軌道を当てる目的で学習していました。目的を変えると平均の誤差が減るか、できる範囲で確かめます。

## 段取り（決めた内容）

- 案22の補正の仕組みをそのまま使います。同じネットワーク（110→112→96→424）と、同じ110次元の記述子、同じ進み方（弾性の粗い経路＋補正ヘッド2 → 拘束 → 4点の距離系列）で、変えるのは学習の目的だけです。
- 目的は「ペアの平均距離を直接当てる」に変えます。損失は、生成した系列の平均（起点距離＋生成した4点の平均）と、実の平均（0〜1 ns の11点の履歴の平均、K08 と同じ定義）との二乗誤差だけにします。座標ごとの一致や状態の損失は使いません。
- 学習に使うタンパク質は生成器の教師8タンパク質（1u84_A、4u5h_G、5hub_A、1x6j_A、2y1y_A、1krn_A、2y4x_B、4xqm_A）で、資料Dの定義の候補（起点 1 ns、起点距離 3.5 Å 超 6.0 Å 以下）を使います。学習の行は約11,028件の見込みです。
- 学習は最初からやり直し、種は元の学習と同じ 722153、AdamW（学習率 0.0015）、16エポック、バッチ 2048 と、元の学習と同じ設定にします。ただし元の学習は CUDA で行われましたが、この仮想マシンには GPU がないので CPU で行います。
- 評価は資料Dの6タンパク質（14,582件）で行い、生成の平均の誤差（平均・ばらつき・相関）を実の平均と比べます。教師8タンパク質での誤差も、学習データそのものの値として別に報告します。

## 読み方（先に固定）

- 平均の誤差のばらつきが複製間のばらつき 0.249 Å より小さくなれば、目的がボトルネックです。
- 0.48 Å 付近のままなら、入力の情報がボトルネックです。

## 実施の経過

- 2026-11-23 22:02 JST に学習データの作成を開始。ATLAS の取得が 3 件続けて途中で切れ（1u84_A は 21,487,240 / 21,496,045 バイト、4u5h_G は 19,349,504 / 19,367,860 バイト、5hub_A は 475,136 / 22,245,413 バイト）、さらに 22:20 JST ごろのサービス再起動で実行が止まりました。途中の作業ディレクトリを掃除して再開したところ、2 回目は 3 件とも取得でき、24 ファイルすべてが揃いました（BUILD DONE、EXIT:0）。再開時の 1 タンパク質あたりの処理は約 35〜70 秒でした。
- 学習は CPU で 27 秒。16 エポックで二乗誤差は 0.3535 → 0.2524 と下がり続けていました（最終 RMSE 0.5023）。
- 評価のスクリプトの最初の版は、候補の並び順を K08 のキャッシュと同じと決めつけていて失敗しました。候補の集合は一致していましたが、並び順が違いました。ドナー原子とアクセプター原子の組み合わせで対応づける形に直し、さらに K08 のキャッシュの実履歴が（11点、候補数）の形であることに合わせて、対応づけを候補の軸で行うよう直しました。

## 結果

### 管道の確認（元の生成器）

`k74_eval.py` で元の生成器を同じ評価にかけたところ、資料Dの6タンパク質 14,582件で平均 −0.1549 Å、ばらつき 0.4830 Å、MAE 0.3170 Å、相関 0.8359 となり、K08 の値（−0.155 / 0.483）と一致しました。評価の管道は正しいです。粗い経路だけ（補正なし）の誤差は平均 −0.1173 Å、ばらつき 0.5014 Å でした。

### 学習し直した生成器（資料Dの6タンパク質、14,582件）

| | 平均 | ばらつき | MAE | 相関 |
|---|---|---|---|---|
| 元の生成器 | −0.1549 Å | 0.4830 Å | 0.3170 Å | 0.8359 |
| 学習し直し | **+0.0243 Å** | **0.4795 Å** | 0.3101 Å | 0.8391 |
| 粗い経路だけ | −0.1173 Å | 0.5014 Å | 0.3151 Å | — |
| 複製間の下限 | — | 0.249 Å | — | — |

タンパク質ごとのばらつき（学習し直し）：1bgf_A 0.489、1ifg_A 0.512、1j8r_A 0.464、2b0a_A 0.470、1mix_A 0.513、2qt4_A 0.405。どのタンパク質でも 0.249 Å には遠く及びません。

### 学習データそのもの（教師8タンパク質、11,028件）での誤差

平均 +0.0009 Å、ばらつき **0.4998 Å**、MAE 0.3266 Å、相関 0.8501。学習データそのものに対しても 0.50 Å を下回りません。

### 系列のゆらぎ（診断）

生成した系列のペアごとのばらつきの平均は、元の生成器で 0.032 Å、学習し直しで 0.107 Å、実の系列では 0.332 Å でした。平均だけの損失でも系列は平らにはならず、むしろ元の生成器よりゆらぎました。ただし実のゆらぎの 3 分の 1 程度です。

## 結論

**先に固定した読み方の 2 本目が当てはまります。入力の情報がボトルネックです。**

平均の目的で学習し直しても、ばらつきは 0.483 Å から 0.480 Å へ 0.0035 Å しか減らず、複製間の下限 0.249 Å の 1.93 倍のままです。変わったのは平均のずれだけで、−0.155 Å から +0.024 Å になりました。

さらに、学習データそのものに対する誤差も 0.4998 Å と、見たことのないタンパク質での誤差（0.4795 Å）と変わりません。モデルが学習データすら 0.50 Å より良く当てられないので、これは汎化の失敗ではなく、110次元の記述子の中に平均を 0.48 Å より良く決める情報がないことを示しています。エポック数を増やしても、同じ入力のままでは大きくは変わらない見込みです（16 エポックの終わりでも損失は 0.255 → 0.252 とゆっくり下がってはいますが、学習データでの誤差が 0.50 Å に張り付いていることが上限を示しています）。

## 注意点（結果を受けて）

- 学習の行は 11,028件で元の学習（110,464件）より少ないですが、学習データそのものの誤差が 0.50 Å であることから、行の少なさが主因ではないと考えられます。行を増やしても、同じ入力では同じ上限にぶつかる見込みです。
- 目的を変えるだけでは平均の誤差は減らないので、G01（座標そのものから平均を学習するモデルの可否測定）では、入力に何を足すかが鍵になります。

## 注意点

- 学習の行（約11,028件、起点 1 ns の候補だけ）は、元の学習の行（110,464件、複数の起点）よりずっと少ないです。学習データの量の違いは、結果の読み方に影響します。
- 平均だけの損失では、生成した系列の時間の形には何も教えません。学習した系列が平らになる可能性があります。系列のゆらぎは診断として別に報告します。
- 学習の目標（0〜1 ns の11点の平均）と、生成する系列（起点より先の4点）は、見る時間の窓が違います。ただし評価する量はこの実の平均そのものなので、目標としては合っています。

## ファイル

- `k74_build.py`：教師8タンパク質の取得・候補の作成・記述子と粗い経路と実履歴の保存（生成器の読み込みはしません）
- `k74_train.py`：平均の損失での学習し直し（CPU）
- `k74_eval.py`：学習し直した生成器での資料Dの6タンパク質の評価
- `k74_train_log.json`：学習の設定とエポックごとの二乗誤差、学習データそのものの誤差、学習し直した重みの SHA-256
- `k74_eval_original.json`：元の生成器での評価結果（管道の確認）
- `k74_eval_retrained.json`：学習し直した生成器での評価結果
- `retrained_generator.pt`：学習し直した生成器の重み（`state`・`center`・`scale` の辞書。SHA-256 は `k74_train_log.json` を参照）
- `training_data/`：教師8タンパク質の学習データ 24 ファイル（記述子・粗い経路・実履歴・実の平均）
