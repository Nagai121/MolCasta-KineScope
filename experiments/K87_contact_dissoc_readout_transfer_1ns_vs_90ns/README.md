# K87: 接触の解離でも、読み出しは予測幅をまたいで使えるか（K50 の条件）

## 仮説

H5（特徴量の抽出と読み出し）に関わる検証です。水素結合の解離では、読み出しは予測幅をまたいできれいには使えませんでした（K75: 1 ns先→90 ns先で 0.61、逆で 0.73。ただし、近い予測幅のあいだの移し替えはよく戻ります）。接触の解離でも同じか確かめます。

読み方は実験前に固定しました。両方向の回復率が 0.8 以上なら、接触の解離でも読み出しは予測幅をまたいで使えます。片方だけ弱ければ、水素結合の 1 ns先→50 ns先の弱さ（K56）と同じ形か、凍結した本体の予測を抜いた条件でも測って確かめます。

## データと条件

- K50 の条件です。弱い土台（資料D）で、ATLAS 解析版 6タンパク質×3レプリカ、学習 1bgf_A・1ifg_A・1j8r_A・2b0a_A（6,383件）、テスト 1mix_A と 2qt4_A の合算（2,915件）、起点フレーム10、履歴 0〜1 ns の11フレーム、予測幅 1/5/10/30/50/90 ns、モデルは HistGradientBoosting（反復120回、学習率0.075、葉31、min_samples_leaf 15、L2 0.02、seed 42）で条件ごとに学習し直しました。距離はフレームごとの箱を軸ごとに扱う周期境界で計算しています（K50 の取り出し時に適用済みで、ここでは K50 のキャッシュをそのまま使いました）。
- 接触の解離: 候補は起点フレーム10の重原子の最小距離が 4.5 Å 以下（接触ができている状態）の残基ペアで、ラベルは予測先のフレームで最小距離が 4.5 Å を超えることです。静的特徴は5個（起点の最小距離、Cα間距離、配列距離の log1p、残基 i と j の重原子の数）、履歴は6統計量（最初の値、平均、標準偏差、最小値、最後−最初、4.5 Å 以下だった割合）です。
- 条件は次の通りです。特徴量は予測幅によらないため、ある予測幅で学習した補正モデルを、すべての予測幅のラベルで評価し、6×6 の表を作りました。利得の測り方は K56 と同じです。ある予測幅で学習した履歴の条件を、別の予測幅で評価したときの利得は、その履歴の条件の AUPRC から、**評価する予測幅で学習した**静的な特徴だけの条件の AUPRC を引いた値です。参照の利得は、評価する予測幅で学習した条件の利得です。戻り率は、移し替えた利得を参照の利得で割った値です。テスト2タンパク質をまとめた値と、タンパク質ごとの平均の両方を見ます。
- 利得の測り方の直し（2026-11-23）: はじめの版では、利得を「学習した予測幅の静的な条件」との差で測っていました。これは K56 と測り方が違い、静的な条件そのものが予測幅をまたいで移りにくいときに、読み出しの移り方が正しく測れません。生の数値（各条件の AUPRC）はそのままに、K56 の測り方で計算し直しました。古いまとめは `results.json` の `_summary_old_definition` に残してあります。直しの計算は `recompute_k56.py` です。直す前は、1 ns先→90 ns先が 0.58、90 ns先→1 ns先が 1.07 と出ていましたが、これは静的な条件の移り方の違いによる歪みでした。
- 確認: 同じ予測幅で学習・評価した条件は、K50 の記録とすべての予測幅で完全に一致しました（AUPRC の差 0.0。1 ns先で静的のみ 0.3105、全部入り 0.5246）。

## 判断

先に固定した8割の線で見ると、**1 ns先→90 ns先は戻りますが、90 ns先→1 ns先は境目です**。1 ns先で学習した補正は 90 ns先で利得の 0.91 が戻り、8割を超えます。90 ns先で学習した補正は 1 ns先で 0.76 と、全体をまとめた値では8割をわずかに下回りますが、タンパク質ごとの平均では 0.87 と8割を超えます。6×6 の表全体では、8割を下回るのは 90 ns先→1 ns先（0.76）と 50 ns先→90 ns先（0.75）の2か所だけで、他はすべて 0.86 以上です。

## なぜ測り直す前と結論が変わったのか

はじめの版では、1 ns先→90 ns先が 0.58、90 ns先→1 ns先が 1.07 と出ていました。これは利得の測り方が K56 と違っていたためで、静的な条件の移り方の違いがそのまま戻り率に出ていました。K56 の測り方に直すと、向きが入れ替わります。理由は次の通りです。

弱い土台（K50 の条件）には凍結した本体の予測が無いため、凍結した予測を抜く確かめは当てはまりません。その代わりに、静的な特徴だけの条件が予測幅をまたいでどう移るかを確かめました。

- 90 ns先で学習した静的な条件は、**すべての評価予測幅でいちばん弱い**静的な条件です（1 ns先 0.2438、5 ns先 0.2429、10 ns先 0.2240、30 ns先 0.2503、50 ns先 0.2504、90 ns先 0.2886）。90 ns先のラベルはばらつきが大きく、静的な条件の学習がうまくいかない形です。
- 逆に、1 ns先で学習した静的な条件は 90 ns先でも強く、AUPRC 0.3517 で、90 ns先で学習した静的な条件（0.2886）を上回ります。
- はじめの測り方では、利得を「学習した予測幅の静的な条件」との差で測っていたため、1 ns先→90 ns先では、移し替えの利得が小さく見えるのと、参照の利得が大きく見えるのが重なって 0.58 になっていました。移し替えの履歴の条件そのものは、90 ns先で AUPRC 0.4588 と、同じ予測幅で学習した履歴の条件（0.4750）と比べて 0.016 しか落ちていません。
- 90 ns先→1 ns先が 0.76 と境目なのは、こちらの向きでは履歴の条件そのものが 1 ns先で 0.052 落ちている（0.4724 に対して、同じ予測幅で学習した履歴の条件は 0.5246）ためです。静的な条件の向きとは逆で、こちらは履歴の条件の移り方そのものが少し弱い形です。

## ファイル

- `run_experiments.py`: 予測幅をまたいだ学習・評価（6×6 の表）、利得と戻り率の計算。途中結果は `results_partial.json` に書き出します。入力は K50 のキャッシュ `~/workspace/kinescope/work/k50_cache/` をそのまま使います。利得の測り方は K56 の定義に直してあります。
- `recompute_k56.py`: 利得の測り方の直し（2026-11-23）。`results.json` の生の数値から、K56 の測り方で `_summary` を計算し直します。古いまとめは `_summary_old_definition` に残します。
- `results.json` / `results.csv`: 全条件の指標と、利得・戻り率のまとめ（`_references_K50` に K50 の記録を同梱）。
