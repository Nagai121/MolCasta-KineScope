# G19: 塩橋の形成で、混合は足しになるか（K15 の広げた条件、塩橋の形成、1 ns先）

## 状態

**実行前の前提確認で、設計が成り立たないことが分かり、止まっています。** 進め方は統括の判断待ちです。この記録は、その前提確認の結果です。

## もともとの設計

G13 では接触の形成で、0.1 ns の切り取り平均に K17 の残基レベル生成平均（第11〜14案）を足すと、回復率が第11〜13案で +0.070〜+0.097 上がりました。塩橋の形成でも同じか確かめる予定でした。条件は K15 の広げた条件（学習58タンパク質・テスト30タンパク質）、1 ns先で、0.1 ns の切り取り平均だけの回復率は 0.647（G03）。ここに K17 の生成平均を足し、切り取り平均だけ（0.647 の再現）と生成平均だけの条件も同じ土台で測るはずでした。判定も先に固定してあります。混合の回復率が切り取り平均だけより +0.05 以上上がる案があれば、混合は塩橋の形成でも足しになる。どの案も +0.05 未満なら、混合の効き目は水素結合と接触に限られる。

## 前提確認の結果

K17 の生成系列は、6タンパク質（1bgf_A・1ifg_A・1j8r_A・2b0a_A・1mix_A・2qt4_A）分の接触候補にしか存在しません。K15 の広げた条件の88タンパク質には、生成系列がありません。K17 の保存値（`~/workspace/k17/out/`、18軌道分）を確認したところ、2vh3_A など広げた条件のタンパク質のファイルが存在しません。

さらに、6タンパク質の範囲でも、塩橋の形成候補と K17 の接触候補は残基ペアとしてはほとんど重なりません。残基ペア（res_i, res_j）の一致で数えた結果は次のとおりです。

| 範囲 | 塩橋の形成候補 | うち K17 の接触候補と一致 | 一致率 | 一致した候補の 1 ns先の陽性 |
|---|---|---:|---:|---:|
| 学習（4タンパク質） | 251件 | 38件 | 15.1% | 1件 |
| テスト（2タンパク質） | 116件 | 20件 | 17.2% | 2件 |
| 参考: 広げた条件全体 | 学習 2,557件、テスト 1,170件 | ― | ― | テスト 93件 |

一致率が低いのは、接触の候補には Cα間距離 12 Å 以下という条件があり、塩橋の候補の多くは荷電残基が離れていてこの条件を満たさないためです。一致したテスト候補は 20件、1 ns先の陽性は 2件しかなく、この部分集合では回復率を測れません。

第22案の生成系列（K05 の `generated_series.npz`）も使えません。K14 で、塩橋・接触にはそのまま使えないことが分かっています（入力の記述子が水素結合の供与体・受容体ペアにしか定義されていないため）。

## 進め方の選択肢

- (A) 第11〜14案を88タンパク質分作り直す。K15 の抽出に使った ATLAS のデータ（`~/workspace/kinescope/work/k15_atlas/`）はこの仮想マシン上にあり、作り直すこと自体は可能です。ただし K17 の6タンパク質分の約15倍の規模になり、弾性モードと局所ゆらぎの計算を88タンパク質×3レプリカ分回す大きな作業です。別途の割り当てと計算資源の判断が要ります。
- (B) 設計を変える。たとえば塩橋の形成の土台を6タンパク質に絞る手はありますが、テストの陽性が 2件しかない部分集合では測れないため、土台を変えてもこの問いには答えられません。
- (C) G19 をこの設計ではやらない。混合の効き目が塩橋の形成でもあるかは、別の生成系列（塩橋の候補に定義できるもの）ができたときに改めて問う。

## 生成系列の作り直し（2026-11-24、Echizen の判断で実施）

上の「進め方の選択肢」の (A) を実施しました。第11〜14案の生成系列を、K15 の広げた条件の88タンパク質分作り直しました。

- 作り方は K17 の `k17_build.py` と同じです（フレーム10の Cα 座標で弾性モードを作り、乱数の種 [506166, レプリカ, 10] を mode_paths → local_paths(omega=0) → local_paths(omega=0.8) の順に消費する。第11・13・14案は原子ごとの変位から、第12案はペアごとのモード選択から作る）。変えたのは候補と距離の定義だけで、候補は K15 の塩橋の形成候補（残基ペアと並びは K15 のキャッシュから取る）、距離は荷電した重原子ペアの最小値（K15 の定義：LYS は NZ、ARG は NE・NH1・NH2、ASP は OD1・OD2、GLU は OE1・OE2）です。
- 軌道は K15 の抽出と同じ場所から MiniTopol の A 形式で読みました（元の6タンパク質は `~/workspace/gpt-model-check/data/trajectories/`、残りは `~/workspace/kinescope/work/k15_atlas/`）。生成にはフレーム10だけが必要です。残基の対応表は K15 の layout をそのまま使い、残基番号が K15 のキャッシュと一致するようにしました。
- 検証は2つしました。1つは、フレーム10の実距離（荷電ペアの最小値）が K15 のキャッシュの hist の最終点と一致すること（全レプリカで確認、誤差 1e-6 未満）。もう1つは、1bgf_A の3レプリカで接触候補の生成系列も作り、K17 の保存値と比べることで、生成の段取りが K17 と完全に同じであることを確認しました（第11〜14案すべてで最大誤差 0.000、ビット単位で一致）。
- 生成系列は `gen/<タンパク質>_R<レプリカ>.npz` に置きました（gen11〜gen14 が (4分岐, 9点, 候補数)、res_i・res_j は K15 のキャッシュのコピー）。タンパク質ごとに区切って作り、できた分から commit しました。既にあるファイルは飛ばすので、途中から再開できます。
- スクリプトは `g19_build.py` です。
