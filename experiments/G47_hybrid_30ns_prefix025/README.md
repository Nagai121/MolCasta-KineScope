# G47: 30 ns先で、0.25 ns の切り取りに生成した平均を足すとどうなるか

## 仮説

H6（運動の生成そのものの問題）に関わる、混合の経路の確認です。G17 では 30 ns先で、0.1 ns の切り取り平均に第22案の生成平均を足すと、回復率が +0.489 上がりました。G32 では 0.5 ns の切り取りで +0.475 上がりました。そのあいだの 0.25 ns の切り取りで測り、30 ns先の混合の効き目が中間の切り取りの長さでも残るか確かめます。

読み方は実験前に固定しました。混合の回復率が切り取り平均だけより +0.05 以上上がれば、30 ns先でも 0.25 ns の切り取りで混合が足しになることになります。+0.05 未満なら、30 ns先では 0.25 ns の切り取りで混合は足しにならないことになります。

## データと条件

- 条件は資料Dの水素結合の形成、30 ns先です。G11・G14・G17 と同じ段取りで、K01 のキャッシュ（`~/workspace/kinescope/work/data_cache/`）と K05 の生成系列（`experiments/K05_generated_quality/generated_series.npz`、第22案の5点系列）を使いました。学習 1bgf_A・1ifg_A・1j8r_A・2b0a_A（9,610件）、テスト 1mix_A＋2qt4_A（4,972件、30 ns先の陽性 345件）。静的特徴は7個、履歴はドナー・アクセプター距離の系列の6統計量（3.5 Å 以下だった割合）です。
- 0.25 ns の切り取りはフレーム [0,1,2]（3フレーム）で、平均はその3フレームの距離の平均です（G02 と同じ）。生成平均は、生成5点系列 [起点距離 d0（フレーム10）, +0.1, +0.3, +0.5, +1.0 ns] の平均です。対応付けのキーは（軌道ID、ドナー原子、アクセプター原子）で、土台候補 14,582件と 100% 対応しました。検証として、生成5点の最初の点と履歴の最終フレーム（起点距離）の最大誤差は、学習側 5.56e-07 Å、テスト側 6.08e-07 Å でした（G11・G14・G17 と同じ値）。
- 条件は次の通りです。静的のみ、全部入り（実履歴6統計量、参照）、切り取り平均だけ、生成平均だけ、混合（切り取り平均＋生成平均の2列）。回復率は、その予測幅での実履歴の利得で割った値です。モデルは HistGradientBoosting（反復120回、学習率0.075、葉31、min_samples_leaf 15、L2 0.02、seed 42）で条件ごとに学習し直しました。距離はフレームごとの箱を軸ごとに扱う周期境界で計算しています（各キャッシュの取り出し時に適用済みで、ここではキャッシュをそのまま使いました）。
- 注意: 生成系列は起点から先への前方系列で、実履歴は起点までの後方系列です。両者は起点距離 d0 を共有しますが時間の向きが逆です（G11・G14・G17・K09 と同じ留保）。ただし平均は向きに依らない量なので、この実験では向きの違いは平均の定義に影響しません（平均の列だけを使うため）。
- 30 ns先の参照の利得は +0.0626（静的のみ 0.3639 → 全部入り 0.4264）で、G17・G32 の記録と一致しました。

## 結果

| 条件 | AUPRC | 利得 | 回復率 |
|---|---:|---:|---:|
| 静的のみ | 0.3639 | — | — |
| 全部入り（実履歴） | 0.4264 | +0.0626 | 1.000 |
| 切り取り平均だけ（0.25 ns） | 0.4298 | +0.0659 | 1.053 |
| 生成平均だけ | 0.3823 | +0.0184 | 0.294 |
| 混合（切り取り平均＋生成平均） | 0.4321 | +0.0682 | 1.091 |

AUPRC はテストの合算です。AUC・Brier・Log Loss は `results.json` を参照。

混合と切り取り平均だけの差は、回復率で **+0.038**（AUPRC で +0.0023）です。

## 判断

先に固定した +0.05 の線で見ると、**30 ns先では 0.25 ns の切り取りで混合は足しになりません**。混合の回復率は切り取り平均だけより +0.038 しか上がらず、線に届きませんでした。

30 ns先の混合の差を切り取りの長さで並べると、0.1 ns で +0.489（G17）、0.25 ns で +0.038（この実験）、0.5 ns で +0.475（G32）と、両端では大きく上がるのに中間だけ上がらない形です。切り取りの長さとともに単調に変わるのではなく、中間だけ落ち込む形です。0.25 ns の切り取り平均だけでも回復率が 1.053 と実履歴の全部入りを上回っているため、生成平均を足す余地が小さい、という読み方もできますが、0.5 ns の切り取り平均だけでも回復率は 1.138（G32）とさらに上で、そこに生成平均を足すと 1.613 まで上がるため、切り取り平均だけの回復率の高さだけでは説明できません。なぜ中間だけ落ち込むのかは、ここからは分かりません。

## 注意点

- 30 ns先の利得そのものが小さめ（+0.0626、全予測幅の中でいちばん小さい）で、テストの陽性も 345件と少ないため、回復率の揺れには注意が要ります（G17 の README の留保と同じ）。混合と切り取り平均だけの AUPRC の差は +0.0023 と小さく、回復率の +0.038 は分母の小ささで膨らんだ見た目になっています。
- 実行は約10秒で終わりました。
