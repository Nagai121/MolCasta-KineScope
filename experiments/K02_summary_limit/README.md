# K02: 実軌道の履歴の要約を生成側と同じ8個に制限する

## 仮説

H5（特徴量の抽出と読み出しの問題）です。生成軌道の実験では、軌道は8個の特徴量に要約されて予測器に渡されていました。実軌道の履歴を同じ8個の要約に制限したときに、指導力がどれだけ残るかを見ます。

## 8個の特徴量の特定について

生成側の資料（notes/B）には8個の中身が書かれていませんでしたが、参照元のコードで特定できました。MolCasta-InternalResearch、ブランチ `research/tseries-models-and-results-20261121` の `research/tseries-exploration-20261121/tseries/hb_trajectory_screen.py` の `summary` 関数です。生成軌道の距離系列（複数の試行経路×8ステップ）について、起点距離との差分（delta）をとり、次の8個を作ります。

1. delta の平均
2. delta の標準偏差
3. delta の最小値
4. delta の最大値
5. 距離が3.5 Å以下だった割合
6. 距離が4.0 Å以下だった割合
7. delta の最終ステップの平均
8. 距離が減ったステップの割合

## この実験での当てはめ方

- 実軌道の履歴は「1本の経路、11フレーム」なので、経路とステップの集計をそのまま履歴系列に当てはめました。起点距離はフレーム10（起点）の距離です。
- 注意点が1つあります。実軌道の履歴では最終フレームが起点そのものなので、7番目の特徴量（最終ステップの delta）は全候補で0になります。生成側では最終ステップは生成の終端で意味を持ちますが、過去方向の履歴に当てはめると、この1個は情報を失います。この点を明記したうえで、残り7個が使える形で実施しました。
- データ、候補、ラベル、分け方、静的特徴量（7個）、モデルは土台と同じです。モデルは条件ごとに学習し直す比較で、履歴側の特徴量だけを土台の6個から生成側の8個に替えました。

## 判断できること

- 実軌道の履歴を生成側と同じ8個の要約に制限しても、指導力は失われませんでした。全予測幅で土台の6個と同等か、それ以上です。
- したがって「8個への要約の形そのものが指導力を消した」という説明は、この土台では成り立ちません。生成側で指導力が出なかった原因は、要約の形式ではなく、要約される前の系列の中身（生成された距離系列そのものが実軌道と違うこと）にある可能性が高くなりました。
- ただし、この実験は実軌道の系列を8個に要約したもので、生成軌道の系列をこの土台で測ったものではありません。生成系列の中身の検証は K05、K06 の担当範囲です。
