# L3-00: 前提確認 — E03 の GBn2 短い MD は CPU で再現できるか

## 仮説

L3 系列（E03・E05 で効いた、水を入れない短い MD = OpenMM の GBn2 陰溶媒 MD について、長さと回復の関係を測る系列）の前提確認です。E03 の測定は GPU（RTX 4060 Ti）で回っていましたが、2026-11-27 の決め事で計算は Colab の CPU セッションを基本とすることになったため、まず (a) CPU で 100 ps にかかる時間を実測し、(b) E03 の対象 25 タンパク質について 4×100 ps の再現（ずれとの相関 +0.5195、静的な予測に足したあとのずれのばらつき 0.603 Å → 0.513 Å の確認）が CPU で届く範囲か確かめます。

## データと条件

- 対象は E03 と同じ 25 タンパク質（ATLAS の未見テストから等間隔に選ばれたもの、R1 のみ）です。候補ペア・実軌道の距離の系列・ラベル・静的な特徴は、E05 の抽出の定義（`extract_l3.py`、土台は E01 の `extract_e01_e02` の関数）でこの仮想マシンに取り直しました。水素結合の形成の候補数は 13,687 件で、E03 の記録と完全に一致しました。他の現象の候補数は、水素結合の解離 6,542 件、接触の形成 20,533 件、接触の解離 8,910 件、塩橋の形成 377 件、塩橋の解離 97 件です。
- 短い MD の手順は E03・E05 と同じです。起点フレーム（フレーム 10）の構造から、水素を付け直し（pH 7.0）、amber14-all と GBn2 陰溶媒で系を組み、200 回の最小化のあと、300 K・2 fs・Langevin で回します。seed は 20261126 から 997 刻みです。
- 起点の確認として、系を組んだ直後の候補ペアの距離が実軌道のフレーム 10 の値と一致することを確かめました（1uha_A をこの仮想マシンで、3t92_A を Colab で確認。最大の差はどちらも 0.00001 Å）。
- 速度の実測は Colab の無料枠の CPU セッション（2 vCPU、OpenMM 8.6.1、プラットフォームは CPU を明示）で行いました。対象は大きさが中央の 3t92_A（120 残基、水素込みで 1,899 原子）です。

## 結果

### CPU での速度（Colab、3t92_A）

| 測ったもの | 値 |
|---|---|
| エネルギー 1 回の計算 | 0.70 秒（3 回とも 0.68〜0.70 秒） |
| 200 ステップ | 143.98 秒（1 ステップ約 0.72 秒） |
| 100 ps（50,000 ステップ）への換算 | 35,994 秒 = **約 10.0 時間** |
| スレッド数を 1 にした場合の 100 ps 換算 | 46,360 秒 = 約 12.9 時間（速くならない） |
| 最小化 200 回 | 7 分では終わらず（エネルギーの単価から約 1,400 秒の見積もり） |

GBn2 は amber14 の定義では CustomGBForce という形で実装されていて、OpenMM の CPU プラットフォームではこの計算が非常に遅いことが原因です。E03 が GPU で測った費用は、全現象込みで 1 タンパク質あたり 4×100 ps が平均 55 秒でした。CPU では同じ 100 ps 1 本に約 10 時間かかります（約 650 倍）。

この仮想マシンでも同じ測り方をしましたが、エネルギー 1 回が 0.97 秒と Colab よりさらに遅く、代替にはなりません。

### 全体の見込み（見積もり）

費用は原子数の 2 乗に比例するとし、実測した 3t92_A を基準に各タンパク質の残基数で換算しました。

- 100 ps 1 本の時間: 最小の 1xmk_A（78 残基）で約 4.2 時間、最大の 2ysk_A（144 残基）で約 14.4 時間。
- E03 の再現（4×100 ps × 25 タンパク質）: **約 914 時間**（最小化の分を入れると約 920〜930 時間）。
- L3 全体（8×100 ps と 1×400 ps = 100 ps 換算で 12 本分 × 25 タンパク質）: **約 2,741 時間**。

## 判断

- **CPU では対象に届きません。** 最小のタンパク質でも 100 ps 1 本に約 4.2 時間かかり、セッションの寿命（無料枠では長くても半日程度）の中で 1 タンパク質の 4 本分すら終わりません。再現の測定（相関とばらつきの確認）は実行していません。
- データの取り直しと手順の組み立ては E03 と一致するところまで確認できています。届かないのは計算の速さだけです。
- 対象は縮めていません。進め方（GPU を使うか、別の計算方法にするか）は Echizen の判断が必要です。L3-01〜L3-06 はこの判断が出るまで止めます。

## 読みの注意点

- 見込み時間は、費用が原子数の 2 乗に比例するという仮定での換算です。実測は 3t92_A の 1 点だけで、タンパク質ごとの原子数や形で前後します。ただし、最小のタンパク質でも 4 時間を超える実測ベースの見積もりで、結論が変わるほどの誤差ではありません。
- 遅いのは GBn2 の CustomGBForce を CPU プラットフォームで計算する場合の話です。溶媒のモデルを GBn2 以外（たとえば GB-OBC）に変えれば速くなる可能性はありますが、それは E03・E05 と違う測定になるため、ここでは試していません。

## ファイル

- `extract_l3.py`: E03 の 25 タンパク質について、全 6 現象の候補・系列・ラベル・静的な特徴を取り直すスクリプト（この仮想マシンで実行）。
- `make_payload.py`: 起点フレームの構造と、ペアの対応付けの情報を、Colab へ送る形にまとめるスクリプト。
- `run_l3_gbn2.py`: GBn2 の短い MD を回し、全現象のペア距離を 10 ps ごとのスナップショットで保存するスクリプト（プラットフォームを指定して使う。タンパク質ごとに保存するので、切れても続きから再開できる）。
- `results.json`: 候補数の照合、起点の確認、速度の実測値、見込み時間の全数値。
- 途中の保存: 取り直した候補などのデータは `~/workspace/kinescope/l3work/extracted/`、Colab へ送った一式は `~/workspace/kinescope/l3work/payload/` にあります（リポジトリには入れていません）。
