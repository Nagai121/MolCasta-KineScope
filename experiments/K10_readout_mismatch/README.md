# K10: 読み出しのずれの切り分け（学習と評価で履歴の出所を入れ替える）

## 仮説

H5（特徴量の抽出と読み出しの問題）の検証です。これまでの比較（K06(a) を含む）はすべて、条件ごとに予測器を学習し直す形でした。学習し直すことで、学習時と評価時で履歴の出所が違うことによる読み出しのずれが隠れている可能性があります。そこで、学習と評価で履歴の出所（実履歴／生成履歴）を入れ替えた4条件を比べます。

読み方は実験前に固定しました。

- (b) が (c) より大きく崩れるなら、喪失には「実履歴で学習した予測器が生成履歴を読みこなせない」という読み出し側の成分があります。
- (b) と (c) が同水準なら、読み出しのずれは小さく、差は系列の中身の側にあることになります。

## データと条件

- データ、候補、ラベル、学習・テストの分け方、静的特徴量（7個）、モデルは土台の再現（`experiments/base_reproduction/`、K07・K08 と同一）です。ATLAS 解析版 6タンパク質×3レプリカ、学習 1bgf_A・1ifg_A・1j8r_A・2b0a_A、テスト 1mix_A と 2qt4_A の合算（候補は学習 9,610件、テスト 4,972件、合計 14,582件）。水素結合形成、起点 1 ns、予測幅 1/5/10/30/50/90 ns、指標は AUC、AUPRC、Brier、Log Loss です。距離はフレームごとの箱を軸ごとに扱う周期境界で計算しています（土台のキャッシュがその定義で作られています）。
- 履歴の特徴量は、実系列・生成系列のどちらも **5点にそろえた系列から同じ6統計量**（最初の値、平均、標準偏差、最小値、最後−最初、3.5 Å以下だった割合）を作ります。特徴量の形がそろっているため、学習側のモデルを評価側にそのまま適用できます。
  - 実系列5点: 履歴 0〜1 ns の11フレームからフレーム [0, 3, 5, 7, 10]（起点から −1.0、−0.7、−0.5、−0.3、0 ns）を取ったもの。K06(a) の S+H5 と同じ定義です。
  - 生成系列5点: 起点距離＋第22案の生成距離4点（+0.1、+0.3、+0.5、+1.0 ns）。生成系列は K05 で作り直した第22案の経路（`experiments/K05_generated_quality/generated_series.npz`）を使い、K06(a) の S+G6 と同じ定義です。対応付けは（軌道ID、ドナー原子、アクセプター原子）で全 14,582 件が1対1に対応し、生成側の起点距離と実履歴の最終フレームの距離の最大誤差は 1e-4 Å 未満でした。
  - 注意: 実系列は起点より前（過去）の系列、生成系列は起点から先（未来）の系列で、向きの違いは K06(a) と同じく「出所の違い」の一部として含みます。
- 条件は次の4つと、参考の静的のみです。交差条件（b）（d）では、学習側の出所で学習したモデルを再学習も再較正もせず、そのまま評価側の出所に適用します。静的特徴量は全条件で共通です。

読み方は実験前に固定したとおりに判定します。主たる読みは 1 ns先です。

- **(b) は (c) より大きく崩れました。読み出しのずれの成分はあります。** 1 ns先で、生成履歴を生成側で学習し直して読む (c) の利得が +0.0362 あるのに対し、実履歴で学習したモデルをそのまま生成履歴に当てた (b) の利得は +0.0052 しかなく、静的のみとほぼ同じ水準まで消えました。(c) の利得のうち約86%（0.0310／0.0362）は、学習し直すことで初めて取り出せる分です。AUC でも (b) 0.9051 は静的のみ 0.9056 と同水準で、Brier と Log Loss は静的のみより悪化しました（0.0460、0.1727）。
- **ただし、中身の差も残ります。** 読み出しを生成側に合わせ直した (c) でも、利得は実履歴 (a) の利得の約41%（0.0362／0.0892）までしか取り戻せていません。「読み出しさえ直せば生成履歴から実履歴並みの指導力が取り出せる」という読みは、この読み出しの形（6統計量＋HistGradientBoosting）では支持されません。喪失は、読み出しのずれと系列の中身の差の両方からなります。
- **ずれは双方向です。** 逆向きの交差 (d) も 1 ns先で静的のみを下回り（0.3397）、10 ns先以降では大きく崩れました（90 ns先 0.2170、静的のみ 0.3035）。「実履歴で学習した予測器が特別」という話ではなく、2つの出所の特徴量の分布が違うため、どちらの向きでも学習時の分割が評価時に合わなくなる、という形です。補助診断のとおり、特に標準偏差と最後−最初は水準も候補ごとの対応も実と生成で大きく違い、木モデルの分割点がそのままでは移らないことと合います。
- これまでの学習し直す比較は、生成側にとって最も有利な読み出しで測っていたことになります。実履歴で学習した予測器に生成履歴をそのまま渡す使い方（実務では自然な使い方）では、1 ns先の利得はほぼ得られません。
- K07（揺らぎを縮めても学習し直せば指導力が残った）とは整合します。学習し直しが効いていた理由の一つは、縮んだ標準偏差の水準に合わせて分割を置き直せることだった、と読めます。
- 予測幅で見ると、(b) と (c) の関係は 10 ns先だけ逆転しました（(b) 0.3811、(c) 0.3353）。K06(a) でも生成側の利得は予測幅でばらついていて、単一の学習 seed の結果である点は他の実験と同じ留保が要ります。1 ns先という主たる読みと、(d) が全幅で (a) を下回る点は一貫しています。

## まだ分からないこと

- 読み出しのずれが、特徴量の尺度をそろえる処理（例: 出所ごとの標準化や、順位・相対量への置き換え）でどこまで取り除けるかは、本実験では試していません。ずれの存在と大きさを示したところまでです。
- (c) がこの読み出しの形での上限に近いかどうかは分かりません。別の特徴量の作り方や予測器では、生成系列からもう少し取り出せる可能性があります（H5 の未検証部分として残ります）。
- 実系列（過去）と生成系列（未来）の向きの違いが、ずれのうちどれだけを占めるかは分離していません。
- 単一の学習 seed の結果であり、ばらつきの範囲は測っていません。

# K10b: 尺度合わせで読み出しのずれはどこまで取れるか

## 仮説

H5（特徴量の抽出と読み出しの問題）の検証です。K10 で、実履歴で学習した予測器を生成履歴にそのまま当てると、1 ns先の利得の約86%が消えました。そこで、生成側の統計量の尺度を実側に合わせる簡単な処理で、このずれがどこまで取れるかを測ります。

読み方は実験前に固定しました。尺度合わせ後の (b) が (c)（生成側で学習し直した条件）や (a)（実履歴）に近づけば、ずれは主に尺度の問題で、将来の生成器は出力の尺度を合わせるだけで読みやすくなるという読みを支持します。ほとんど変わらなければ、ずれは尺度ではなく分布の形の側の問題ということになります。

## 方法

- 生成側の6統計量を、統計量ごとに実側の分布へ線形に合わせます。`gen_scaled = (gen − μ_gen) / σ_gen × σ_real + μ_real` で、μ・σ は学習タンパク質だけで求めます（学習側の実5点と生成5点の各統計量の平均・標準偏差）。評価側のデータでは変換のパラメータを決めていないので、漏れはありません。
- 変換後の生成統計量を、K10 の (b) と同じ実履歴学習モデル（静的7＋実 hist6 で学習、seed 42）で評価します。モデルは学習し直していません。
- 変換の倍率（学習タンパク質で決めたもの）: 最初の値 1.50、平均 1.18、標準偏差 **7.13**、最小値 1.11、最後−最初 **4.07**、3.5 Å以下の割合 0.95。標準偏差と最後−最初は大きく引き伸ばす変換です。変換後のテスト側の生成統計量の平均・標準偏差は、実テスト側の値とよく合いました（例: 標準偏差の平均は変換後 0.338 に対し実 0.316）。
- (b) の尺度合わせなしの値は K10 の results.json から引用します。初回の K10b 実行時に別ループで (b) を再現したところ、全6予測幅で AUPRC が小数第4位まで K10 の (b) と一致したことを確認しています。

|---:|---:|---:|---:|---:|---:|
| 1 ns | 0.3637 | 0.4529 | 0.3689 | **0.3845** | 0.3999 |
| 5 ns | 0.3493 | 0.4471 | 0.3240 | **0.3662** | 0.3345 |

## 判断できること

読み方は実験前に固定したとおりに判定します。主たる読みは 1 ns先です。

- **1 ns先では、尺度合わせで利得の約半分が戻りましたが、(c) には届きませんでした。** 尺度合わせなしの利得 +0.0052 に対し、尺度合わせありでは +0.0208 になり、(c) の利得 +0.0362 の約57%、(a) の利得の約23%まで回復しました。事前に固定した二分法（(c) に近づくか、ほとんど変わらないか）のどちらにもきれいには当てはまらず、中間です。ずれのうち尺度で説明できる分は確かにあり、同時に尺度では取り除けない分も残ります。
- **予測幅によって効果はまちまちです。** 尺度合わせは 1 ns先（+0.0156）、5 ns先（+0.0422、(c) と静的のみも上回る）、30 ns先（+0.0178、(c) にほぼ並ぶ）、90 ns先（+0.0295、(c) を上回る）では改善しましたが、10 ns先（−0.0507、静的のみも下回る）と 50 ns先（−0.0163）では悪化しました。単一の学習 seed の結果でもあり、「尺度合わせは常に効く」とは言えません。
- **順位は良くなっても、較正は良くなりません。** 1 ns先で AUC は 0.9051 → 0.9120、Log Loss は 0.1727 → 0.1606 と改善しましたが、Brier は 0.0460 → 0.0473 と静的のみ（0.0432）よりさらに悪化しました。標準偏差を約7倍、最後−最初を約4倍に引き伸ばす変換は、生成側の小さい揺らぎを実側の水準まで膨らませるため、その統計量のノイズも一緒に膨らみ、確率の較正を崩しうる、という解釈と合います。
- K10 の補助診断と合わせると、尺度で直せるのは「分布の位置と広がり」までで、候補ごとの対応の弱さ（標準偏差の相関 0.171）や符号の逆転（最後−最初の相関 −0.189）は線形の尺度合わせでは直りません。残りのずれは分布の形と対応の側にある、という読みになります。将来の生成器が「出力の尺度を合わせるだけ」で読みやすくなる、という読みは、この結果では支持されません。尺度合わせは改善の方向には働きますが、(a) には遠く、(c) にも届きません。

## まだ分からないこと

- 予測幅ごとの効果のばらつき（10 ns先・50 ns先の悪化）が、学習 seed のばらつきか、変換の構造的な副作用（ノイズの増幅）かは、本実験だけでは分かりません。
- 尺度合わせを「生成系列そのもの」に当てる（統計量ではなく系列の振幅を合わせる）形や、順位・分位点への置き換えなど、別の合わせ方がどこまで取れるかは試していません。
- 単一の学習 seed の結果であり、ばらつきの範囲は測っていません。

## コードと出力

- `k10b_run.py`: 本実験のコードです。変換のパラメータは学習タンパク質だけで決め、途中結果を `results_k10b_partial.json` に予測幅ごとに書き出すため、仮想マシンの再起動で中断しても再開できます（実行中に一度再起動で中断し、この仕組みで再開して完了しました）。
- `results_k10b.csv` / `results_k10b.json`: 尺度合わせありの全指標、変換のパラメータ、1 ns先のまとめです。(b) の尺度合わせなしの値は K10 の results.json からの引用です。
- 実行はこの仮想マシン上です（Colab は使っていません）。

# K12b: 読み出しのずれの強い土台での確認

## 仮説

H5（特徴量の抽出と読み出しの問題）の検証です。K06(b) で、強い土台（凍結した本体 T1I2006＋補正モデル、未見100タンパク質）では、生成側で学習し直した条件（c 相当）でも生成特徴は補正に何も足さないことが分かりました。そこで、K10 の「実履歴で学習した予測器を生成履歴に当てると利得がほぼ消える」という結論が、強い土台でも成り立つかを確かめます。

読み方は実験前に固定しました。強い土台でも (b) が静的補正と同水準かそれ以下なら、読み出しのずれの結論は強い土台でも成り立つことになります。(b) が K10 の弱い土台での結果よりずっと良ければ、ずれは土台の強さに依存するということになります。

## 方法

- K06(b) の計算済み特徴をそのまま使います（`~/workspace/k06b/run/k06b_out/` の108タンパク質分）。軌道の取り直しはしていません。学習は較正8タンパク質（13,808件）、評価は未見100タンパク質×3複製（163,074件）です。補正モデルの学習器は K06(b) の eval_b.py と同一です（HistGradientBoosting、160本、学習率0.065、葉15、葉あたり最小20件、L2 0.15、seed 20261121）。
- 次元の問題への対応：実履歴は DocA の10特徴、生成は6特徴で、そのままでは学習と評価の出所を入れ替えられません。そこで実履歴から K10 と同じ6統計量だけを取り出しました（history の列 [0,1,2,3,5,7] = 最初の値・平均・標準偏差・最小値・最後−最初・3.5 Å以下の割合。K10 の hist6 と同一の定義）。生成側は保存済みの gen6 をそのまま使います。静的5特徴は全条件で共通です。このため交差条件の (a) の比較相手は (a6)（実6→実6）になります。K06(b) の (a10)（実10→実10）は引用で併記します。

## 判断できること

読み方は実験前に固定したとおりに判定します。

- **強い土台でも、(b) は静的補正と同水準どころか、はっきり下回りました。** 1 ns先で (b) は AUPRC 0.4004 で、静的補正 0.4591 を −0.0587 下回り、(c) 0.4526 も下回ります。すべての予測幅でマイナスで、90 ns先では −0.0865 です。K10 の結論は強い土台でも成り立ちます。事前に固定した読みの二択のうち、(b) が弱い土台よりずっと良くなる、という側は否定されました。
- **弱い土台より、むしろ悪化が大きくなっています。** 弱い土台（K10）では (b) の利得は +0.0052 と、静的のみとほぼ同じ水準でした。強い土台では −0.0587 と、静的補正を大きく下回ります。ずれが土台の強さに依存する、という読みも、この方向では支持されません。強い土台ほど実履歴への依存が大きく（(a6) の利得 +0.0706）、読み違えた履歴の害も大きくなる、という解釈と合います。
- **(b) は補正しない（凍結のみ）よりも悪くなります。** 1 ns先で凍結のみ 0.4929 に対し (b) は 0.4004 です。実履歴で学習した補正を生成特徴に当てると、補正が凍結した本体の順位付けを壊す方向に働きます。Brier（0.0526、静的補正 0.0479 より悪い）と Log Loss（0.1778、静的補正 0.1579 より悪い）でも同じ傾向です。
- **(d) も崩れるので、ずれは双方向です。** 生成6で学習して実6で評価しても、1 ns先で 0.4115（利得 −0.0476）と静的補正を大きく下回ります。K10 の (d) と同じ向きの結果です。
- **(a6) と (a10) はほぼ同じです。** 1 ns先で (a6) 0.5297 に対し (a10) 0.5293、利得は +0.0706 に対し +0.0702（全体）、macro では +0.0707 に対し +0.0712 です。DocA の10特徴のうち、交差に使った6統計量だけで実履歴の利得はほぼ全部取れており、残りの4特徴（最大値・最後−2番目・4.5 Å以下の割合・増加の割合）は利得にほとんど寄与しません。交差の比較相手として (a6) を使うことは妥当です。
