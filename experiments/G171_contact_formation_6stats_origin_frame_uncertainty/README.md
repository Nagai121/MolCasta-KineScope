# G171: 接触の形成で、起点のフレームを入れるかどうかでの 6 個の統計量の回復率の差に、区間を付ける（資料Dの条件、接触の形成、1・5・10・30・50・90 ns先）

## 1. 2 つの条件の定義（結果を見る前に固定）

- 軌道の保存間隔は 100 ps（0.1 ns）。フレーム k は時刻 k*0.1 ns。
- **6stats10（フレーム [0..9] の 10 フレームの 6 個の統計量）**: G123・G128 の「1.0 ns の切り取り」と同じ。実際に覆う長さは 0.9 ns で、起点フレーム 10 は入らない。
- **6stats11（フレーム [0..10] の 11 フレーム全部の 6 個の統計量）**: 0〜1 ns の履歴全部で、起点フレーム 10 が入る。実際に覆う長さは 1.0 ns。全部入りの条件そのものなので、回復率は定義上 1.0 になる（G157 で確かめ済み）。
- 6 個の統計量は、最初の値、平均、標準偏差、最小値、最後−最初、閾値（4.5 Å）以下だった割合。条件は「静的特徴＋6 個の統計量」で、ほかの履歴統計量は使わない。起点フレーム10（1 ns）は変えない。
- 回復率 =（その条件の AUPRC − 静的のみ）÷（その予測幅での実履歴の利得）。回復率の差 = 6stats11 の回復率 − 6stats10 の回復率。AUPRC の差 = 6stats11 の AUPRC − 6stats10 の AUPRC。

## 3. 区間の計算方法（結果を見る前に固定）

- 再標本化の単位はタンパク質。テストは 2 タンパク質（1mix_A・2qt4_A、テスト候補は 1mix_A が 5,012件、2qt4_A が 2,372件）だけなので、区間は 3 つの値の最小値と最大値の形で粗くなります。2 タンパク質から復元抽出で 2 タンパク質を選び直すと、取りうる組み合わせは (1mix_A, 1mix_A)、(1mix_A, 2qt4_A)、(2qt4_A, 2qt4_A) の 3通りだけで、区間はその3値の最小値〜最大値に等しくなります。「0 を含む／含まない」は実質的に「2タンパク質の差の向きが一致しているか／食い違っているか」と同じ読みです（G23・G49・G59・G62・G67・G114・G130 と同じ留保）。30 タンパク質の G162・G163・G164 のような細かい区間ではありません。
- ブートストラップの回数と乱数 seed は結果を見る前に固定した: 10,000回、seed 42。区間はパーセンタイル法（2.5%点と 97.5%点）。G73・G49・G59・G62・G67・G23・G147・G148・G162・G163・G164 と同じである。
- 回復率の差の区間の計算では、各ブートストラップ標本の中で、静的のみ・全部入り・6stats10・6stats11 の AUPRC を測り直し、利得（全部入り − 静的のみ）と 2 つの回復率をその標本の中で計算し直してから差を取る。つまり回復率の分母の土台の利得は、標本ごとに測り直す（G147・G148・G162・G163・G164 と同じ）。全体の利得で固定してはいない。
- AUPRC の計算は、sklearn の average_precision_score と同じ段取り（しきい値で区切って精度と再現率を取り、再現率の増え分で重み付けする）を numpy で書き直したもので、実際の予測確率で sklearn の値と 1e-12 まで一致することを確かめてから使った（コード内の assert で確認）。
- 候補ごとの予測確率は、ブートストラップの前に `test_predictions.npz` に保存した。
- ブートストラップの値の種類数（n_distinct）は、回復率の差・AUPRC の差とも 6 予測幅すべてで 3 でした。3通りしかないことの確認になっています。

## 5. 読み取り（先に固定した読み方に沿う）

- **区間の水準でも差があると言えるのは、30 ns先だけです。** 30 ns先は回復率の差 −0.129（区間 [−0.165, −0.065]）、AUPRC の差 −0.0195（区間 [−0.0210, −0.0128]）で、起点のフレームを入れると回復率が下がる向きです。G157 で点推定が大きく見えた 50 ns先（+0.138）と 90 ns先（+0.115）は、区間の水準では差があるとは言えません。
- ほかの 5 予測幅（1・5・10・50・90 ns先）は、回復率の差の区間も AUPRC の差の区間も 0 を含み、区間の水準では差があるとは言えません。50 ns先は点推定が +0.138 と 6 予測幅の中で最も大きいですが、タンパク質ごとの差の向きが食い違い（1mix_A +0.193、2qt4_A −0.027）、区間は [−0.027, +0.193] と 0 を含みます。90 ns先も同じで、点推定は +0.115 ですが区間は [−0.110, +0.219] と 0 を含みます。AUPRC の差で見ても、50 ns先は [−0.0093, +0.0289]、90 ns先は [−0.0310, +0.0306] と 0 を含みます。
- ただし区間は 2 タンパク質だけの粗いもので、「0 を含まない」は「2タンパク質の差の向きが一致している」と同じ読みです。30 ns先の差が、3つめのタンパク質でも同じ向きになるとまでは、この実験だけでは言えません。G162（30 タンパク質）では区間が 0 を含まない予測幅は 1 つもなく、G171 の 30 ns先の「0 を含まない」は 2 タンパク質の粗い区間での話である点に注意が要ります。

## 7. 起点のフレームを入れることの正当性について

- フレーム 10 の距離（履歴の最後の値）は、静的特徴の 0 列目にも入っている。K13 の抽出コードでは静的特徴の 0 列目は `hist[-1]`（フレーム 10 の距離）で、今回の再計算でも静的特徴の 0 列目と履歴の最後の値の差の最大値は学習側・テスト側とも 4.8e-07 Å だった。つまり 6stats11 の条件は、静的特徴にすでに入っているフレーム 10 の距離を、6 個の統計量の形でもう一度入れる形になる。2 つの条件の比べは「新しい情報を足すかどうか」ではなく「統計量の作り方をどうするか」の比べである。
- 起点のフレーム（フレーム 10）は予測時点そのものの構造なので、静的な入力の一部として入れるのは正当である。これは設計上の判断であって、実験の結果そのものではない。6 個の統計量にフレーム 10 を入れるかどうかは、その判断の範囲の話である。
