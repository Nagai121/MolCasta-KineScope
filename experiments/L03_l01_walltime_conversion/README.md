# L03: L01 の曲がりを実時間に換算する（G04 の費用実測による机上の換算）

- 確かめること: L01 は回復率を「覆う長さ（ns）」に対して測ったが、分母はシミュレーションの長さで、実測の費用への換算は G04 の後に回されていた。L03 では新しい計算はせず、G04 で実測した短い実MDの費用（固定の費用＋本番の速さ）を使って、L01 の曲がりの横軸を覆う長さから実時間に換算し、回復率と実時間の関係（時間あたりの回復率を含む）を出す。
- 状態: 完了（机上の換算のみ）。回復率 0.8 と 0.9 に届く最小の長さである覆う長さ 0.6 ns は、実時間では約 15.1 時間にあたる。時間あたりの回復率は覆う長さ 0 ns（固定の費用のみ、0.399/時）が最大で、生産を走らせる長さの中では 0.1 ns（0.180/時）が最大。0.5→0.6 ns の段は実時間でも残り、この区間だけ時間あたりの回復率が上がる（0.0607→0.0683/時）。

## 1. 何をする記録か

L01 の曲がり（資料Dの条件、水素結合の形成、1 ns先、切り取りの平均だけ、覆う長さ 0〜1.0 ns を 0.1 ns 刻みの11通り）の横軸を、G04 の実測費用で実時間に換算する。L01 が「長さあたりの戻り方」を出したのに対し、L03 は「時間あたりの戻り方」を出す。新しい学習・評価は一切していない。回復率は L01 の記録の値をそのまま使い、時間は G04 の記録の値から式で出した。

## 2. 使った数値と出典

### L01 の回復率

- 出典: `experiments/L01_hb_formation_leverage_1ns/results.json` の `recovery_vs_real_history_gain`（README の表と同じ値）。
- 土台: 静的のみ AUPRC 0.3637、全部入り 0.4815、実履歴の利得 +0.1178。回復率 0.8・0.9 に届く最小の覆う長さはどちらも 0.6 ns。

### G04 の費用（すべて `experiments/G04_short_md_cost/README.md` の「再測定の結果（CPU、2026-11-24）」から）

- 計算機と系: この仮想マシンの CPU（AMD EPYC 9D64、GROMACS 2023.3、MPI 1本・OpenMP 4スレッド）、1mix_A（206残基、約55,700原子、AMBER99SB-ILDN＋TIP3P、2 fs刻み）。
- 準備の各段: pdb2gmx 0.674 秒、editconf 0.096 秒、solvate 0.935 秒、grompp（イオン用）0.792 秒、genion 0.697 秒、合計 約 3.2 秒。
- エネルギー最小化: 832.1 秒（1,239歩で収束）。
- 平衡化: NVT 10 ps が 1,001.6 秒（0.878 ns/日）、NPT 10 ps が 964.8 秒（0.906 ns/日）、合計 1,966.4 秒。**平衡化は元の mdp の 100 ps ではなく、10 ps の区間で実測し、その実測値を固定の費用に入れた**（G04 の記録どおり）。
- 固定の費用（準備＋最小化＋平衡化）: 約 2,802 秒（約 46.7 分）。内訳の合計は 3.2＋832.1＋1,966.4 ＝ 2,801.7 秒で、G04 の換算は 2,802 秒を使っているため、L03 も 2,802 秒を使う。
- 本番の速さ: 1.007 ns/日、23.823 時間/ns（＝ 85,762.8 秒/ns）。
- **平衡化を 100 ps にした場合の見積もりは、G04 の記録にない。** G04 の README の「まだ分からないこと」に「平衡化を元の mdp の 100 ps で回した場合の固定の費用（今回は 10 ps の区間で測り、その実測値を固定の費用に入れた）」と明記されており、100 ps の場合の固定の費用は未測定である。そのため L03 では 100 ps の場合の実時間は併記できない。

## 3. 換算の式と前提

- 合計時間（秒）＝ 固定の費用 2,802 秒 ＋ 生産の長さ（ns）× 85,762.8 秒/ns（23.823 時間/ns）。これは G04 自身の換算式と同じで、G04 の換算表（0.1 ns → 11,378 秒、0.5 ns → 45,683 秒、1.0 ns → 88,565 秒）と L03 の値が一致することを確かめた。
- **「覆う長さ」と生産の長さの対応**: L01 の覆う長さ L ns の履歴は、時刻 0〜L ns のフレーム 0〜(L/0.1) を使う。これを新たに短いMDで得るには、平衡化の後に生産MDを L ns 走らせ、その軌道の始めから L ns 分を使う必要がある。したがって生産の長さ ＝ 覆う長さとする。固定の費用は生産の長さによらず 1 回だけかかる。
- 覆う長さ 0 ns は生産 0 ns で、合計は固定の費用のみ（2,802 秒、約 0.78 時間）になる。フレーム0だけなら本来は MD 自体が不要で費用はほぼ 0 とも読めるが、G04 の費用の形（系の準備＋平衡化までを 1 回の実行の固定の費用とする）に合わせて、固定の費用のみで計上した。この行の時間あたりの回復率（0.399/時）は「準備だけして生産を走らせない」場合の値で、他の行とは意味が違う点に注意する。
- 時間あたりの回復率 ＝ 回復率 ÷ 合計時間（時間）。
- 前提の限界: G04 の費用は 1mix_A 1本・この仮想マシンの CPU での実測である。タンパク質の大きさや計算機（GPU など本番が速い環境）が変われば、固定の費用の割合も含めて値は変わる。L01 の回復率は資料Dの条件（テスト 2タンパク質）の値で、タンパク質ごとのばらつき（0.6 ns で 1mix_A 1.190、2qt4_A 0.850）がある。

## 5. 読み取り

- **回復率 0.8 と 0.9 に届く最小の長さ（覆う長さ 0.6 ns）は、実時間では約 15.1 時間（54,260 秒）にあたる。** 0.5 ns（約 12.7 時間）では回復率 0.770 と届かず、0.6 ns まで約 2.4 時間長く走らせると回復率が 1.029 へ跳ねる。L01 で見えた 0.6 ns の段は、実時間に直しても段として残る。
- **時間あたりの回復率は、生産を走らせる長さの中では 0.1 ns が最大（0.180/時）で、長くするほど下がる**（0.2 ns で 0.117/時、1.0 ns で 0.042/時）。ただし例外が 0.5→0.6 ns で、この区間だけ 0.0607 から 0.0683/時へ上がる。回復率の増え分（+0.260）が大きいためで、段のところでは「長くするほど効率が落ちる」が当てはまらない。
- 固定の費用の割合は 0.1 ns でも 24.6% で、0.6 ns では 5.2% まで下がる。この環境（本番 1.007 ns/日と遅い）では、G04 の読み取りどおり、固定の費用は短い実行でも支配的にはならない。費用の大半は生産の時間である。
- 回復率そのものの頂点は 0.7 ns（1.145、約 17.5 時間）で、1.0 ns（約 24.6 時間）まで伸ばしても回復率は 1.042 と下がる。実時間で見ても、1.0 ns まで走らせる意味はこの条件では無い。
- 覆う長さ 0 ns の行（0.399/時）は固定の費用のみで割った値で、生産を伴わないため他の行と直接は比べられない。フレーム0の 1 点にも利得の約 3 割がある（L01）という事実とあわせて読む値である。

## 6. 判断できること・まだ分からないこと

- 判断できること: G04 の実測費用（この仮想マシンの CPU、1mix_A）の下では、L01 の回復率 0.8・0.9 に届く最小の実行は生産 0.6 ns で約 15.1 時間。時間あたりの回復率は 0.1 ns が最大で、0.5→0.6 ns の段の区間だけが例外的に上がる。固定の費用（約 46.7 分）は、0.1 ns の実行でも全体の約 4 分の 1 にとどまる。
- まだ分からないこと: 平衡化を元の mdp の 100 ps で回した場合の固定の費用（G04 の記録になく、未測定）。GPU など本番が速い計算機での換算（固定の費用の割合が大きくなる）。タンパク質の大きさが違う場合の費用。強い土台での曲がり（L02）に対する換算は L02 の完了後に追記する。
- L02 の曲がりについての同じ換算は、L02 が終わったあとにこの記録へ追記する（今回の作業には含めていない）。
