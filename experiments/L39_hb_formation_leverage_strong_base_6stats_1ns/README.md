# L39: 統計量6種で L01 の曲がりを強い土台で測る（K06(b) の条件、水素結合の形成、1 ns先）

- 確かめる仮説: H6（運動の生成そのものの問題）に関わる、「短い実MDを安くする」経路の L 系列の続き。L02（強い土台、未見100タンパク質×3レプリカ）では、履歴は切り取りの平均だけを使い、回復率 0.8 に届く最小の覆う長さは 0.7 ns、0.9 に届く最小の長さは全体で 0.8 ns だった。ここでは履歴の要約を平均だけではなく統計量6種（実験Dの定義）に広げ、同じ土台・同じ長さの定義で曲がりを測り直して、必要な長さが縮むかを見る。
- 状態: 完了。**統計量6種では、必要な長さは 0.1 ns 縮んだ。** 回復率 0.8 に届く最小の長さは 0.6 ns（平均だけでは 0.7 ns）、0.9 に届く最小の長さは全体・タンパク質ごとの平均とも 0.7 ns（平均だけでは全体 0.8 ns、平均 0.9 ns）。同じ長さで比べると、0.2 ns 以降は 0.3 ns を除いて6種が平均だけを上回り、差は 0.7 ns で最大（全体 +0.146）。ただし 0.1 ns では6種が平均だけを下回る（全体 0.446 対 0.545）。増え幅がいちばん大きい場所は 0.1→0.2 ns（全体 +0.203）で、平均だけの場合（0→0.1 ns）に比べて段の位置が 1 区間後ろにずれた。

## 1. 何を確かめる実験か

実の 0〜1 ns の履歴を、始めの短い部分だけに切って使う。切り取りの長さを L01・L02 と同じ11通り（覆う長さ 0〜1.0 ns、0.1 ns 刻み）に変え、各長さで「切り取りの統計量6種」を履歴の特徴量として強い土台の補正モデルに入れたときの 1 ns先の利得の回復率を測る。あわせて、各長さの回復率にタンパク質単位の再標本化によるブートストラップ 95% 区間を付ける。比較のために、L02 とまったく同じ作り方の「切り取りの平均だけ」の条件も同じ実行で学習し直し、回復率を並べる。

読み方は先に固定した（L02 と同じ）。

1. 回復率 0.8 に届く最小の長さと、0.9 に届く最小の長さを、統合値（全体、pooled）で読む（タンパク質ごとの平均（macro）も併記する）。L02（平均だけ）の答えと比べて、縮んだかどうかを明記する。
2. 段の判定は、隣り合う長さの間の回復率の増え幅がいちばん大きい場所と、その大きさで読む。
3. 信頼区間はタンパク質単位のブートストラップ 10,000回（seed 42、パーセンタイル法）で付ける。各標本の中でも静的のみ・全部入り・各長さの AUPRC を測り直し、利得と回復率をその標本の中で計算し直す。
4. 段の前後ではタンパク質ごとの値も記録する。

## 2. 条件

- 土台は K06(b)（強い土台）と同じ。凍結した本体モデル T1I2006＋補正モデル HistGradientBoosting（160回、学習率 0.065、葉 15、葉あたり最小 20件、L2 0.15、種 20261121）。較正タンパク質 8つで学習し、未見の100タンパク質×3レプリカ（163,074行、1 ns先の陽性 11,712件）で評価する。静的特徴は5個。
- 起点フレーム10（1 ns）、履歴 0〜1 ns の11フレーム（100 ps 間隔）、ラベルは 1 ns先。条件ごとに学習し直す。
- 系列は G05 で作り直したもの（`~/workspace/kinescope/work/g05_series/`、タンパク質ごとの `r{r}_series`、11点×候補数）をそのまま使う。静的特徴と履歴の要約値10個は K06(b) の保存値（`~/workspace/k06b/run/k06b_out/`）を使う。実行はローカルVM（学習24条件と premise の照合で約1分、ブートストラップ 10,000回で約19分、全体約20分）。

### 統計量6種の定義（実験Dの定義どおり）

統計量6種は、実験D（固定した 1 ns 履歴の実験）の `features_from_history` の定義をそのまま使う。出典は MolCasta-InternalResearch ブランチ `research/fixed-1ns-3phen-6h-20261121` の `GPT遊び場/ATLAS-実軌道-2026-11-19/fixed_1ns_history_3phen_6h.py` で、並びは次の通り。

1. 最初の値（系列の最初のフレームの距離）
2. 平均
3. 標準偏差（ddof=0、numpy の `std` の既定）
4. 最小値
5. 最後−最初（系列の最後のフレーム − 最初のフレーム）
6. 閾値以下だった割合（閾値は水素結合の形成の境界 3.5 Å。同スクリプトの `THRESH["hb"] = 3.5` で、割合は `(series <= bound).mean`）

値は float32 に落とす（同スクリプトの作り方どおり）。切り取りへの適用は、同じ式を切り取りの部分系列（フレーム 0〜k）にそのまま適用する。「最後」は切り取りの最後のフレーム、「割合」は切り取りの中での割合になる。覆う長さ 0 ns（1フレーム）では標準偏差と最後−最初は 0 になり、割合は「最初の値が 3.5 Å以下かどうか」の 0/1 になる。

### K06(b) の履歴特徴10個との関係

K06(b) の全部入りの履歴特徴10個は、同じ g05_series の11フレームから次の式で再現できる（下の premise で全数照合した）。

| 位置 | K06(b) の要約値10個 | 実験Dの6種に入るか |
|---:|---|---|
| 0 | 最初 | 入る（1番目） |
| 1 | 平均 | 入る（2番目） |
| 2 | 標準偏差 | 入る（3番目） |
| 3 | 最小 | 入る（4番目） |
| 4 | 最大 | 入らない |
| 5 | 最後−最初 | 入る（5番目） |
| 6 | 最後−直前 | 入らない |
| 7 | 3.5 Å以下割合 | 入る（6番目） |
| 8 | 4.5 Å以下割合 | 入らない |
| 9 | 増加割合（隣り合うフレームで増えた割合） | 入らない |

つまり実験Dの6種は K06(b) の10個の部分集合で、10個は6種に「最大、最後−直前、4.5 Å以下割合、増加割合」の4つを足した拡張である。したがって全部入り（11フレーム全部の要約値10個）は6種の上位集合で、覆う長さ 1.0 ns の6種の条件は、全部入りから4特徴を落とした条件にあたる。

### 長さの呼び方（L01・L02 と同じ、結果を見る前に固定）

長さは「覆う長さ」で統一し、定義は L01・L02 にそのまま合わせた。軌道の保存間隔は 100 ps（0.1 ns）で、フレーム k は時刻 k×0.1 ns。覆う長さ L ns の切り取りはフレーム 0〜(L/0.1) を使う（0 ns はフレーム0だけの1フレーム、1.0 ns はフレーム 0〜10 の11フレーム全部）。起点フレーム10（1 ns）は変えず、ラベルは 1 ns先のまま。G 系列の呼び方との対応も L02 と同じで、L39 の覆う長さ 1.0 ns は G05 の「全部」側の定義（11フレーム全部）であり、G145 の「1.0 ns」（フレーム [0..9]）とは違う。

### 条件の一覧（1 ns先）

- 静的のみ: 静的特徴5個だけ。
- 全部入り（full_history）: 静的特徴＋実履歴の要約値10個（0〜1 ns の11フレーム）。回復率の分母（実履歴の利得）の参照。
- 切り取りの平均だけ: 静的特徴＋切り取りの平均だけ。覆う長さ 0.0〜1.0 ns の11通り。L02 とまったく同じ作り方（premise の照合と比較用）。
- 切り取りの統計量6種: 静的特徴＋切り取りの統計量6種。覆う長さ 0.0〜1.0 ns の11通り（主役）。

回復率 =（その長さの AUPRC − 静的のみ）÷（実履歴の利得）。全体（pooled）とタンパク質ごとの平均（macro）の両方で測る（L02 と同じまとめ方）。macro の AUPRC は、陽性が0件でも全部でもないタンパク質（100タンパク質すべてが該当）ごとの AUPRC の平均。

## 3. ブートストラップの段取り（結果を見る前に固定、L02 と同じ）

- 回数: 10,000回。乱数 seed: 42。区間はパーセンタイル法（2.5%点と 97.5%点）。
- 再標本化の単位: タンパク質。テストの100タンパク質から復元抽出で100タンパク質を選び直す。
- 各ブートストラップ標本の中でも、静的のみ・全部入り・各長さの AUPRC を測り直し、実履歴の利得と回復率をその標本の中で計算し直した。モデルは学習し直さず、学習済みのモデルの候補ごとの予測確率（`test_predictions.npz` に保存）を再標本化している。6種と平均だけの両方の系列を、同じ抽出で測っている。
- 全体の AUPRC の計算は L02 と同じ numpy 実装（sklearn の average_precision_score と同じ段取り）を使い、実際の予測確率で全24条件について sklearn の値と 1e-9 未満まで一致することを確かめてから使った。
- 10,000回の抽出すべてで、標本内の実履歴の利得は全体でもタンパク質ごとの平均でも 0 以下にならなかった（回復率が定義できない抽出は 0 件）。

## 4. 結果

### 土台の再現（premise）

3つの照合をすべて通過した（詳細は `premise_check.json`）。

1. **統計量の定義の照合**: 較正8＋テスト100 の全108タンパク質×3レプリカ（324本すべて）で、g05_series の11フレームから上の式で再計算した要約値10個が、K06(b) の保存値（`~/workspace/k06b/run/k06b_out/` の `r{r}_history`）と最大差 3.8e-6 で一致した（float32 の丸めの範囲。基準は 1e-4 未満）。6種の部分集合についても同じ最大差だった。統計量6種の定義が既存の記録と結びつくことを確認した。
2. **土台の再現**: 1 ns先で静的のみ AUPRC は全体 0.4591、タンパク質ごとの平均 0.4539。全部入りは全体 0.5293、タンパク質ごとの平均 0.5251。利得は全体 +0.0702、タンパク質ごとの平均 +0.0712 で、K06(b) の記録（`~/workspace/k06b/results_100.json` の `by_horizon` の 1 ns先）と L02 の基準（5e-4 以内）で一致し、L02 の実行値とも完全に一致した。
3. **平均だけの回復率の照合**: 同じ実行で学習し直した平均だけの条件の回復率は、全11長さ×全体・平均の22項目すべてが L02 の記録（`experiments/L02_hb_formation_leverage_strong_base_1ns/results.json` の `recovery_vs_real_history_gain`）と 5e-3 以内で一致した（実際は表示4桁まで一致）。6種のうち平均が L02 と同じ入力になっていることを確認した。

### 先に固定した読み方への答え

1. **回復率 0.8 に届く最小の長さ: 覆う長さ 0.6 ns**（全体 0.862、タンパク質ごとの平均 0.845）。平均だけ（L02）では 0.7 ns だったので、**0.1 ns 縮んだ**。**回復率 0.9 に届く最小の長さ: 覆う長さ 0.7 ns**（全体 0.982、タンパク質ごとの平均 0.959）。平均だけでは全体 0.8 ns、タンパク質ごとの平均 0.9 ns だったので、**全体で 0.1 ns、平均で 0.2 ns 縮んだ**。

| 0.8 ns | 0.930 | 1.044 | +0.114 | 0.896 | 1.033 | +0.136 |
| 0.9 ns | 1.028 | 1.055 | +0.027 | 0.994 | 1.028 | +0.034 |
| 1.0 ns | 0.975 | 1.006 | +0.031 | 0.957 | 0.992 | +0.035 |

- **必要な長さは 0.1 ns 縮んだ**（0.8 の線: 0.7→0.6 ns、0.9 の線: 全体 0.8→0.7 ns、平均 0.9→0.7 ns）。縮み幅は刻み 1 つ分で、劇的ではない。
- 同じ長さでの差は、0.2 ns 以降は 0.3 ns を除いて6種が一貫して上回り、特に 0.6〜0.8 ns で大きい（全体 +0.088、+0.146、+0.114）。平均以外の要約値（ばらつき、最小、割合など）は、履歴がある程度の長さになってから効く形である。
- 例外が2つある。0.1 ns（2フレーム）では6種が平均だけを大きく下回る（全体 −0.100）。2フレームでは標準偏差や最後−最初は平均とほぼ同じ情報しか持たず、特徴が増えた分だけ学習が不利になった可能性があるが、この実験では切り分けていない。もう1つは 0.3 ns で、差は全体 −0.031 と小さい。
- 覆う長さ 0 ns（1フレーム）では、6種のうち標準偏差と最後−最初は 0 で、実質は「最初の値」と「3.5 Å以下だった割合（= 最初の値が 3.5 Å以下かどうか）」の2つになる。それでも平均だけ（= 最初の値そのもの）より全体 +0.036 高く、境界に対する二値の情報が足しになっている。
- 曲がりの形はどちらも滑らかで、頂点のあと 1.0 ns でわずかに下がる点も共通する（6種は 0.9 ns の 1.055 が頂点、平均だけは 0.9 ns の 1.028 が頂点）。

## 5. 読み取り

- **統計量6種を使うと、必要な覆う長さは 0.1 ns 縮む**（0.8 の線で 0.7→0.6 ns、0.9 の線で全体 0.8→0.7 ns）。平均以外の要約値は、特に 0.6〜0.8 ns の範囲で回復率を +0.09〜+0.15 押し上げる。ただし縮みは刻み 1 つ分にとどまり、短い切り取りの効き方の骨格（最初の 0.1〜0.2 ns で大きく戻り、その後緩やかに積み上がる）は変わらない。
- 増え幅最大の場所は平均だけの 0→0.1 ns から 0.1→0.2 ns へずれた。6種では最初の 2 フレーム（0.1 ns）時点の回復率が平均だけより低い分、3 フレーム目（0.2 ns）でまとめて上がる形になっている。段と呼べる突出ではなく、増え分は 0.5→0.8 ns にも +0.09〜+0.12 ずつ残っている。
- 覆う長さ 1.0 ns では、6種だけで全部入り（要約値10個）の AUPRC に並んだ（全体 0.5297 対 0.5293）。1 ns先の予測では、全部入りの残り4特徴（最大、最後−直前、4.5 Å以下割合、増加割合）はほぼ足しになっていない。分母の利得そのものが6種でほぼ回収できるため、回復率の天井は平均だけの場合（1.0 ns で 0.975）より 1 に近い 1.006 になった。
- 費用の側は L02 と同じくまだ何も言えない。分母はシミュレーションの長さ（ns）で、実測の費用への換算は L03 の形（G04 の実測との対応付け）で行う。

## 6. 判断できること・まだ分からないこと

- 判断できること: 強い土台（未見100タンパク質×3レプリカ、水素結合の形成、1 ns先）で履歴に統計量6種を使うと、回復率 0.8 に届く最小の覆う長さは 0.6 ns、0.9 に届く最小の覆う長さは 0.7 ns（全体・タンパク質ごとの平均とも）で、平均だけの場合より 0.1 ns（0.9 の線の平均では 0.2 ns）短い。増え幅がいちばん大きいのは 0.1→0.2 ns（全体 +0.203）で、突出した段はない。覆う長さ 1.0 ns では6種だけで全部入り（要約値10個）に並ぶ。
- まだ分からないこと: 90 ns先でも必要な長さが縮むか（L40 の担当）。0.1 ns で6種が平均だけを下回る理由（特徴が増えたことによる学習の不利か、2フレーム時点の要約値の情報の乏しさか）。6種のうちどの要約値が 0.6〜0.8 ns の押し上げを担っているかは、この実験では切り分けていない。
