# K82 1 ns先で学習した読み出しが 50 ns先で弱いのは、凍結した本体の予測に頼る形が違うからか（K06(b) の条件、水素結合の形成）

- 確かめる仮説: H5（特徴量の抽出と読み出しの問題）に関わる読み出しの移し替え
- 状態: 完了。凍結した本体の予測を抜くと 1 ns先→50 ns先の移し替えの弱さが消えました（回復率 0.608 → 0.936／0.943）。弱さは、凍結した本体の予測への頼り方の違いによるものです。

## 1. 何を確かめる実験か

K56 で、1 ns先で学習した読み出しを 50 ns先で使うと利得の戻り率は 0.608 と弱いことが分かりました。K79 で逆向きは 1.026・1.330 と強いことも分かりました。K80 で、頼る統計量の違いでは弱さを説明できませんでした（1 ns先の読み出しは 50 ns先でも担い手である平均に頼っている）。次に残るのは、補正モデルへの入力のうち履歴以外の部分、つまり凍結した本体の予測です。K61 で、長い予測幅の読み出しに要るのは凍結した本体の予測確率だと分かりました（これを落とすと 50 ns先の保持率は 0.38、90 ns先では利得がマイナス）。では、凍結した本体の予測を抜いたら移し替えの弱さは消えるか確かめます。

読み方は先に固定しました。凍結した本体の予測を抜いたら移し替えの弱さが消えれば、弱さはその頼り方の違いです。抜いても弱さが残れば、弱さは別の理由です。「弱さが消える」とは、1 ns先→50 ns先の回復率が 0.608 から 8割以上に上がることです。

## 2. 条件

- 土台は K06(b) と完全に同じです。凍結した本体 T1I2006＋補正モデル（HistGradientBoosting、反復160回、学習率0.065、葉15、葉あたり最小20件、L2 0.15、種 20261121）で、較正用の8タンパク質（2vh3_A、3ga3_A、3wx4_A、3ol3_A、2es9_A、2in8_A、2iay_A、1lsl_A、候補 13,808件）で学習し、未見100タンパク質×3レプリカ（163,074件）で評価しました。特徴量は K06(b) の保存済みデータ（`~/workspace/k06b/run/k06b_out/`）をそのまま使いました。軌道の取り直しも、本体 T1I2006 の読み込みも、生成器のチェックポイントの読み込みも行っていません。距離の計算もしていません。
- 補正モデルの静的特徴5つの中身は、K06(b) の作り方から次の通りです。0: 凍結した本体 T1I2006 の予測確率、1: 予測のもとの供与体・受容体間の距離、2: 供与体・受容体の残基の CA 間距離、3: 供与体が主鎖の N か側鎖か、4: 受容体が主鎖の O か側鎖か。保存済みデータの静的特徴の 0列目が、保存済みの `r*_frozen` 配列と一致することを確かめました（float32 の丸めの範囲、最大差 3e-08）。
- 条件は2通りです。
  - 入れた条件（with）: 静的5特徴＋実履歴10特徴。K56・K79 と同じ条件です。
  - 抜いた条件（without）: 静的特徴の 1〜4列目＋実履歴10特徴。凍結した本体の予測確率の列だけを落としたもので、K61 の drop_frozen と同じ入力です。
- 学習・評価の組み合わせは4通りです。(1,1) は 1 ns先で学習して 1 ns先で評価、(1,50) は 1 ns先で学習して 50 ns先で評価（K56 の弱さが出る条件）、(50,50) は 50 ns先で学習して 50 ns先で評価、(50,1) は 50 ns先で学習して 1 ns先で評価（K79 の逆向きの確認）です。
- 利得の定義に注意してください。補正モデルの利得は、評価する予測幅での静的な特徴だけの条件との AUPRC の差です。抜いた条件では、静的な特徴だけの条件も同じく特徴0を抜いた形で作り直し、抜いた条件同士で比べました。つまり「抜いた条件の利得」＝（特徴0を抜いた実履歴の補正 − 特徴0を抜いた静的のみの補正）です。K61 の利得の測り方（落とした条件の履歴を、静的な特徴5つ全部の静的のみの条件と比べる）とは基準が違うため、K61 との照合は K61式の利得も別に計算して行いました（3.3 を参照）。
- 移し替えの回復率＝（移し替えた条件の利得）÷（同じ評価幅で学習した条件の利得）で、入れた条件と抜いた条件のそれぞれについて、同じ条件の中だけで計算しました。
- 実行中にサービスが1回再起動しましたが、実行コードは途中結果を `results_partial.json` に書き出す作りで、再起動後に結果ファイルを確認したところ16件の学習・評価がすべて終わっていました。結果ファイルは再起動の影響を受けていません。

## 3. 結果

### 3.1 利得（AUPRC、全体まとめ／タンパク質マクロ平均）

| 条件 | 1 ns → 1 ns | 1 ns → 50 ns | 50 ns → 50 ns | 50 ns → 1 ns |
|---|---:|---:|---:|---:|
| 入れた条件の利得 | +0.0702 / +0.0712 | +0.0216 / +0.0213 | +0.0354 / +0.0344 | +0.0720 / +0.0709 |
| 抜いた条件の利得 | +0.1490 / +0.1485 | +0.1015 / +0.1015 | +0.1085 / +0.1076 | +0.1428 / +0.1403 |

### 3.2 移し替えの回復率（全体まとめ／タンパク質マクロ平均）

| 条件 | 1 ns → 50 ns | 50 ns → 1 ns |
|---|---:|---:|
| 入れた条件 | **0.608 / 0.618** | 1.026 / 0.995 |
| 抜いた条件 | **0.936 / 0.943** | 0.958 / 0.945 |

### 3.3 対照の確認

- 入れた条件の 4通りの組み合わせは、K06(b)・K56・K79 と小数第4位まで一致しました。(1,1) と (50,50) の静的のみ・実履歴は K06(b) と全4指標で完全一致（最大差 0.0、1 ns先で静的のみ 0.4539、実履歴 0.5251、50 ns先で静的のみ 0.4407、実履歴 0.4752）。(1,50) の戻り率 0.608／0.618 は K56 の 0.61／0.62 と、(50,1) の戻り率 1.026／0.995 は K79 の 1.026／0.996 と一致しました。
- K61式の利得（落とした条件の履歴を、静的な特徴5つ全部の静的のみの条件と比べたもの）は、1 ns先で +0.0635／+0.0644、50 ns先で +0.0133／+0.0136 で、K61 の表（1 ns先 +0.0635、50 ns先 +0.0133）と小数第4位まで一致しました。

### 3.4 絶対値の内訳（AUPRC、全体まとめ）

抜いた条件の利得が入れた条件よりずっと大きいのは、静的な特徴だけの条件が凍結した本体の予測を抜くと大きく落ちるためです。1 ns先で静的のみは 0.4591 → 0.3736、50 ns先で 0.4470 → 0.3518 と落ちます。一方、実履歴の補正は 1 ns先で 0.5293 → 0.5226 とほとんど落ちず、50 ns先でも 0.4825 → 0.4603 と落ちは小さいです。つまり履歴の統計量は、1 ns先では凍結した本体の予測の代わりをほぼ果たせますが、50 ns先では代わりきれません（K61 の「長い予測幅では凍結した本体の予測が要る」と同じ形です）。

## 4. 読み取り

- **凍結した本体の予測を抜くと、1 ns先→50 ns先の移し替えの弱さが消えました。** 回復率は入れた条件の 0.608／0.618 から、抜いた条件では 0.936／0.943 に上がり、先に固定した8割の線を超えました。先に固定した読み方の1つ目の枝に当たり、弱さは凍結した本体の予測への頼り方の違いによるものです。
- 逆向き（50 ns先→1 ns先）の回復率は、入れた条件の 1.026／0.995 から抜いた条件では 0.958／0.945 と少し下がりますが、8割以上は保ちます。抜いても両方向とも8割以上です。
- 絶対量でも、移し替えの弱さは縮みました。入れた条件では、1 ns先で学習した読み出しを 50 ns先に当てたときの利得は +0.0216 で、同じ 50 ns先で学習した条件の +0.0354 との差は 0.0139 でした。抜いた条件では、移し替えた利得は +0.1015 で、同じ 50 ns先で学習した条件の +0.1085 との差は 0.0070 と半分になります。
- どう読むか。凍結した本体の予測があると、1 ns先で学習した読み出しはその予測に大きく頼り、履歴の統計量は小さな修正にしか使いません。その使い方は 1 ns先に合っていて、50 ns先には合いません。凍結した本体の予測を抜くと、読み出しは距離・種類の特徴と履歴の統計量だけで予測を組み立てなければならず、その組み立て方は予測幅によらず同じ形になるため、移し替えが利きます。K80 の結果（頼る統計量の違いでは説明できない）と合わせると、弱さの理由は履歴の統計量の側ではなく、凍結した本体の予測との組み合わせ方の側にあります。
- ただし、凍結した本体の予測が長い予測幅で要らないという意味ではありません。3.4 の通り、50 ns先では凍結した本体の予測があるほうが実履歴の補正の絶対値は高いです（0.4825 対 0.4603）。凍結した本体の予測は、50 ns先の読み出しの水準を上げる一方で、1 ns先で学習した読み出しを 50 ns先に移すときの足かせになる、という両面があります。

## 5. 判断できること・まだ分からないこと

- 判断できること: 1 ns先で学習した読み出しが 50 ns先で弱いのは、凍結した本体の予測への頼り方の違いによるものです。凍結した本体の予測を抜くと回復率は 0.608 から 0.936（全体まとめ）／0.943（タンパク質マクロ平均）に上がり、先に固定した8割の線を超えました。K80 で統計量の側では説明できなかった弱さが、凍結した本体の予測の側で説明できました。
- まだ分からないこと: 1 ns先で学習した読み出しが、凍結した本体の予測を具体的にどう使っているか（どの値の範囲で頼り、履歴の統計量とどう組み合わせているか）。また、凍結した本体の予測への頼り方を 1 ns先と 50 ns先で直接比べる段取り（たとえば、凍結した本体の予測の値で候補を分けて移し替えを測る）は、この実験ではしていません。
