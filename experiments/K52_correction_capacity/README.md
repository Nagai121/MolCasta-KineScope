# K52: 補正モデルを強くすると、実履歴の利得は増えるか（強い土台、水素結合）

## 仮説

H5（特徴量の抽出と読み出し）に関わる検証です。これまでの補正モデルは、設定を固定した HistGBM でした。補正モデルを強くすると、実履歴の利得が増えるか確かめます。

読み方は実験前に固定しました。容量を大きくして利得がはっきり増えれば、読み出しのモデルが限界でした。利得が変わらなければ、情報は今のモデルで取り切れています。

## データと条件

- K06(b) の条件です。凍結した本体 T1I2006 に補正モデル（HistGradientBoosting、学習率0.065、min_samples_leaf 20、L2 0.15、seed 20261121）を付け、較正用の8タンパク質（候補 13,808件）で学習し、未見の100タンパク質×3レプリカ（候補 163,074件）で評価します。予測幅は 1/5/10/30/50/90 ns、指標は AUC、AUPRC、Brier、Log Loss です。利得は静的補正との AUPRC の差で、全体をまとめた値とタンパク質ごとの平均の両方を見ます。
- 容量は4通り（あとで2通り追加）です。学習率・min_samples_leaf・L2 は K06(b) と同じにしています。
  - base: 学習回数160回、葉15（K06(b) の設定）
  - iter2x: 学習回数320回、葉15
  - leaves63: 学習回数160回、葉63
  - big: 学習回数320回、葉63
- 容量ごとに、静的な特徴だけの条件と実履歴の条件の両方を測り、利得は同じ容量どうしで比べます。
- 対照の確認: base の静的な特徴だけの条件と実履歴の条件は、K06(b) の記録と全予測幅で完全に一致しました（AUPRC の差 0.0）。

## 途中で見つかった問題：学習回数の2倍が効いていなかった

iter2x の利得が base と全予測幅で完全に一致したため調べたところ、HistGradientBoosting の既定の早期停止（early_stopping='auto'）が原因でした。較正用の候補が 13,808件と 10,000件を超えるため早期停止が働き、base も iter2x も 78回で止まっていました。leaves63 も 55回で止まっていました。つまり、学習回数を2倍にしても、実際には同じ回数で止まっていたため、容量は増えていませんでした。big が leaves63 と一致したのも同じ理由です。

そこで、早期停止を切った条件を2つ追加して測り直しました。

- iter2x_noes: 学習回数320回、葉15、早期停止なし（実際に320回まわります）
- big_noes: 学習回数320回、葉63、早期停止なし

## 判断

先に固定した読み方だけを見ると、big_noes では利得が全予測幅ではっきり増えたので「読み出しのモデルが限界」に見えます。ですが、絶対値を見ると逆です。big_noes では静的な特徴だけの条件も実履歴の条件も、両方とも悪くなっています。

| 予測幅 | 静的な特徴だけ：base → big_noes | 実履歴：base → big_noes |
|---|---:|---:|
| 1 ns | AUPRC 0.4591 → 0.4052、Brier 0.0479 → 0.0538、Log Loss 0.1579 → 0.1971 | AUPRC 0.5293 → 0.4835、Brier 0.0451 → 0.0517、Log Loss 0.1485 → 0.2000 |
| 90 ns | AUPRC 0.4418 → 0.3716、Brier 0.0556 → 0.0617、Log Loss 0.1860 → 0.2269 | AUPRC 0.4683 → 0.4195、Brier 0.0542 → 0.0613、Log Loss 0.1812 → 0.2334 |

利得が増えたのは、実履歴の条件が良くなったからではなく、静的な特徴だけの条件のほうが大きく悪くなったからです。較正用の候補が 13,808件と少ないため、容量を大きくすると較正用に過剰に合ってしまい、未見のタンパク質では両方の条件が悪くなります。静的な特徴だけの条件のほうが悪くなり方が大きいので、差し引きの利得だけが増えて見えます。予測そのものは悪くなっているので、容量を大きくしても情報は増えていません。

葉の数を増やしただけの条件（leaves63、早期停止あり）では、利得は 1・5・10・50 ns先でわずかに下がり、30・90 ns先でわずかに上がる、というまちまちな結果で、はっきりした増加はありません。学習回数だけを増やした条件（iter2x_noes）でも、利得は 1 ns先で下がり、他はほぼ変わりません。

まとめると、読み出しのモデルが限界というより、情報は今のモデルで取り切れています。容量を大きくすると、較正用の少ないデータに過剰に合ってしまい、未見のタンパク質での予測が悪くなります。
