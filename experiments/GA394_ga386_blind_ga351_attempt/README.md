# GA394 GA386 の GA351 盲採点の試行（採点データ不足で停止）

**この試行は、Echizen の指示（2026-11-25）で、どすこい側（生成器の実証チャット）が実施したものです。** GA 系列でどすこい側が担当する初めての試行です。凍結済みの GA386 を、GA384 の盲採点とまったく同じ採点経路で GA351 パネル（予約済み ATLAS 8 配列、3,980 ペア）で 1 回だけ採点する計画でした。

## 結論

**採点は実行できませんでした。** 採点経路が必要とする GA351 パネルの生成アンサンブル（2 つの力場の生成軌道の要約ファイル）が、リポジトリのどのブランチにも、この仮想マシンにも存在しませんでした。親 GA348 の再現確認も同じ理由で実行できていません。割り当ての決め事どおり、再現できない場合は記録して止めることにしました。

## 確認できたこと

- GA386 の固定条件は development.json の記録どおりです。best は「expanded-1.0-40/0.35」（40 エポック、固定混合 35%）、検証の残差相関は全 9 起点 0.615022、後続 0.600048 で、割り当ての指定と一致しました。
- チェックポイント `expanded-1.0-40.pt` は GA386 のディレクトリにあります。SHA-256 は `1ed2a094cdd68fd58f2238082e1715c94aa8d7af1045d56107a8d75f9c5e4618` です。GA386 の記録側にハッシュの記録（generator.json 等）はないため、照らす先はありませんでした。値はこの README と result.json に記録しました。
- 採点に使う XGBoost のモデル 4 つ（GA318 の all-8.ubj、GA330 の all-9.ubj、GA347 の all-9.ubj、GA344 の generated-6.ubj）は、すべて各実験ディレクトリに commit されています。
- パネルの target・static・タンパク質の対応（3,980 ペア分）は blind-ga351.npz にあります。
- 親 GA348 の従来の値は blind-ga351.json の記録どおりです（残差相関 0.621945、RMSE 0.499672、残差 SD 0.499486、バイアス −0.013660）。GA384 の値は残差相関 0.622139、RMSE 0.500598 です。

## 足りないもの

採点経路（ga351_confirm.py → ga384_confirm.main の blind 実行）の中で、components（ga348）と inputs（ga344）は、タンパク質ごとに 2 つの力場の生成アンサンブルのファイル `{タンパク質}-49.npz`（pair と tracks を含む）を読みます。GA351 パネルについては、つぎの 16 ファイルが Codex 側の runs 環境にしかありません。

- `runs/ga351/blind/amber/{5b1n_A, 1utg_A, 5h1n_B, 1uha_A, 1wq8_A, 4f55_A, 5dje_B, 1vr8_A}-49.npz`
- `runs/ga351/blind/charmm/{同上 8 ファイル}`

親 GA348 のペアごとの予測も、GA386 の頭部への入力特徴量も、この 16 ファイルから計算されます。blind-ga351.npz に保存されているのは GA384 の混合済み予測（0.8 × 親 + 0.2 × GA384 の頭部）だけなので、親の予測を後から取り出すことはできません。全ブランチの履歴を確認しましたが、盲パネルについて commit されたのは blind-ga351.json と blind-ga351.npz だけです（GA321 の予約パネルでは生成アンサンブルが commit されていますが、GA351 ではされていません）。

## 生成し直さなかった理由

生成アンサンブルは OpenMM のシミュレーション（ga351_generate.py）で、locked.json にはタンパク質・起点・窓・分岐数・刻み・最小化の記録はありますが、乱数の種の記録はありません。ここで生成し直すと別のパネルになり、親 GA348 の従来の値（残差相関 0.621945 など）は再現されず、GA384 の盲採点と同じ採点経路にはなりません。割り当ての決め事（再現しなければ記録して止める）に従いました。

## 先に固定した読み方（未実施）

- 同一の 3,980 ペアで、GA386 と GA348 の残差相関・残差 SD・RMSE・バイアスを並べて記録する。
- GA386 の相関が GA348 を +0.005 以上上回り、かつ RMSE が悪化していなければ「盲採点でも上積みが残った」と記録する。それ以外は数値をそのまま記録する。
- 0.700 の線についても触れる。現時点では GA386 の盲採点の値がないため、0.700 への言及はできません。検証の値（0.615022）の時点でも 0.700 には届いていません。

## 再開（2026-11-25）

アーカイブのコミット（e083600）が入り、生成アンサンブルの 16 ファイルが `experiments/GA351_sequence_disjoint_reserve/blind/` にそろいました。ブランチの先端は 82c2c2a です。16 ファイルを確認したところ、Amber は 8 分岐、CHARMM は 2 分岐で、各タンパク質の pair の配列は両力場で一致し、合計 3,980 ペアで blind-ga351.npz と一致しました。タンパク質ごとのペア数は 5b1n_A 331、1utg_A 351、5h1n_B 344、1uha_A 460、1wq8_A 506、4f55_A 621、5dje_B 676、1vr8_A 691 です。生成側はこれでそろいました。

それでも採点は実行できませんでした。採点経路は生成アンサンブルだけでなく、実軌道から候補と静的な特徴量を作る共有のモジュールも使います。そのうち frontends（data）、gc_history（past）、g2i_path35（paths）、explore（record）の 4 つは、どのブランチにも commit されておらず、この仮想マシンにもありません。ga_static_offset は 4 つとも読み込み時に使うため、候補の組み立て（cohort）と特徴量の抽出（extract）が動きません。GC ブランチに gc_history.py の写しはありますが、frontends・g2i_path35・explore はどこにもありません。実軌道も、予約 8 配列分（各 1001 フレーム × 3 レプリカ）はこの仮想マシンにありません（ここの atlas-workspace には 1mix_A だけです。tseries.data.acquire で ATLAS から取り直すことはできますが、モジュールがないため採点は動きません）。

足りないモジュールをこちらで書き直すことはしませんでした。それでは GA384 の盲採点と同じ採点経路にはならないからです。決め事どおり、記録して止めます。

## 再開の条件（更新）

共有のモジュール 4 つ（frontends.py、gc_history.py、g2i_path35.py、explore.py）を、採点経路が使った形で commit してもらえれば採点できます。あるいは、パネルのペアごとの親予測と入力特徴量（x, d）の配列でも構いません。その場合は実軌道がなくても採点できます。
