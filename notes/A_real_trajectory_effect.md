# A. 実軌道の指導力に関する主要実験（T1I2006 初期履歴実験）の事実整理

調査対象: リポジトリ `Nagai121/MolCasta-InternalResearch`、ブランチ `research/t1i2006-100ns-1us-extrapolation-20261121`、`research/tseries-exploration-20261121/` 配下の資料。読み取りのみで確認した。

## 1. 実験条件

### 対象現象とラベル

- 対象は水素結合の「形成」です。ただし実際の水素結合そのものではなく、ドナー・アクセプター重原子間の距離による代理ラベルです（`t1i2006_initial_history_100.py` 冒頭の説明、`results_100.json` の `task` 欄）。
- 候補ペアは、予測起点の時点で距離が 3.5〜6.0 Å の範囲にあるドナー・アクセプター重原子ペアです（実験コードのスクリーニング条件。起点で 3.5 Å 以上＝まだ結合していないペアに限ります）。
- ラベルは、未来の対象時刻にそのペアの距離が 3.5 Å 以下になっていれば 1、そうでなければ 0 です。距離は周期境界を考慮して計算されています（実験コードの `_mic` 呼び出し）。
- 塩橋と接触はこの実験では扱っていません。モデル T1I2006 が水素結合専用だからです（実験コード冒頭）。

### 時刻の関係

- 入力に使う実軌道は絶対時刻 0〜1 ns です。ATLAS の analysis 軌道（100 ps 間隔）で、フレーム 0〜10 の 11 フレーム分です。
- 予測起点は絶対時刻 1 ns（フレーム 10）です。候補ペアと静的特徴はこの時点の構造から作ります。
- 予測幅は起点から 1 / 5 / 10 / 30 / 50 / 90 ns で、ラベルに対応する未来時刻は絶対時刻で 2 / 6 / 11 / 31 / 51 / 91 ns です（`results_100.json` の `target_absolute_ns`、実験コードの `TARGETS`）。
- 特徴量には未来の座標は一切入っていません（実験コードに明記され、履歴特徴はフレーム 0〜10 のみから計算されています）。

### 入力特徴量

比較した2つの補正モデル（後述）の入力は次のとおりです（実験コード `one_replica` 関数）。

- 共通の静的特徴（5個）:
  - 凍結した T1I2006 本体が出した予測確率（起点の構造から計算）
  - 起点でのドナー・アクセプター間距離
  - 候補ペアの基礎記述子3個（`frame()` が返す base 配列の第1・第3・第5成分。この実験ファイル内では中身の名前は書かれていません）
- 履歴特徴（10個）: 候補ペアのドナー・アクセプター間距離の時系列（0〜1 ns、11フレーム）から計算した統計量です。
  - 0 ns 時点の距離、平均、標準偏差、最小値、最大値
  - 最後の距離 − 最初の距離、最後の距離 − 1つ前の距離
  - 距離が 3.5 Å 以下だったフレームの割合、4.5 Å 以下だったフレームの割合
  - 距離が増えたステップの割合
- 「初期履歴あり」条件は静的5個＋履歴10個の計15個、「構造のみ」条件は静的5個だけを使います。履歴特徴は候補ペア自身の距離の動きだけを集計したもので、周囲の原子の運動や速度などは入っていません。

### モデル構成

- 本体モデル T1I2006 は凍結して使いました。再学習はしていません。T1I2006 は2つのモデル（T1I1451 と T1I1453）の重み付き平均（重み 0.90625 と 0.09375）です（実験コード `prepare_model`）。
- 本体の上に、小さな補正モデル（HistGradientBoosting、木の本数160・学習率0.065・葉の数15など、実験コード `learner` 関数）を2種類用意し、予測幅ごとに別々に学習しました。
  - 構造のみ補正モデル: 静的特徴5個で学習
  - 初期履歴つき補正モデル: 静的＋履歴の15個で学習
- 2つの補正モデルの学習データ・学習設定は完全に同じで、違うのは特徴量だけです。つまりこの実験は「予測器を固定した比較」に近い形で、履歴特徴の追加効果だけを取り出しています。

### 学習データと評価データの分け方

- 補正モデルの学習には、評価用とは別の8タンパク質×3レプリカ＝24軌道を使いました（較正用タンパク質: 2vh3_A、3ga3_A、3wx4_A、3ol3_A、2es9_A、2in8_A、2iay_A、1lsl_A。`results_100.json` の `calibration_proteins`）。
- 評価は未見の100タンパク質×3レプリカ＝300軌道です（`results_100.json`）。
- 未見性の担保は厳しめです。T1I2006 の開発に使った学習・検証・テスト・過去パネルと追加学習リストのタンパク質をすべて除外し、さらに UniProt が重なるもの、配列の一致度が 0.35 を超えるものも除外しています。長さ70〜150残基、ATLAS の非冗長チェーンから、CATH 分類のバランスを見て選んでいます（実験コード `select_pool`）。
- 候補ペアの総数は全予測幅で共通の 163,074 件で、陽性数は予測幅ごとに 11,712 件（1 ns）〜13,111 件（30 ns）と変わります（`raw/atlas100/summary.csv`）。
- 35配列実験は100配列実験に含まれる部分集合で、独立した追試ではありません（README.md）。

## 2. 指導力の測定結果

### 改善量の定義

- ここでの改善量は「初期履歴つき補正モデル − 構造のみ補正モデル」の差です（README.md に明記）。
- 「+0.0712 @1ns」と「+0.0273 @90ns」は、ATLAS 100配列での **AUPRC のタンパク質マクロ平均の改善量**です。手順は、タンパク質ごとに両条件の AUPRC を計算し、その差を100タンパク質で平均したものです。出所は `effect_curve.csv`（atlas100、auprc、protein_macro の行）と `results_100.json` の `improvement_vs_static` で、両者は一致します（1 ns: 0.07122、90 ns: 0.02726）。
- 95%信頼区間は、タンパク質を単位として3000回再標本化するブートストラップで求めています（集計コード `aggregate_t1i2006_history_100.py`）。

### 予測幅ごとの改善量（ATLAS 100配列、タンパク質マクロ平均）

## 3. 比較の基準条件

- 基準は「構造のみ補正モデル」です。凍結した T1I2006 本体の出力確率を含む静的特徴5個だけで学習した補正モデルで、本体モデルそのものではありません。
- 比較対象の「初期履歴つき補正モデル」は、同じ静的特徴に履歴特徴10個を足したものです。学習データ（同じ8タンパク質）、学習設定、評価データは共通で、違いは履歴特徴の有無だけです。
- したがって +0.0712 という数字は「既存モデルの素の性能からの改善」ではなく、「同じ土台に履歴特徴を足したときの改善」です。実際、凍結した本体そのものと比べると、履歴あり補正モデルの AUPRC は候補ミクロで 0.49292 → 0.52930、差は +0.0364 です（1 ns、`raw/atlas100/summary.csv` から計算）。構造のみ補正モデルは本体そのものより AUPRC が低い点にも注意が必要です（0.45908 対 0.49292）。

## 4. データの出所と保存場所

- 実験は GitHub Actions で実行されました。`manifest.json` に出典の run ID が記録されています（35配列: 44887394482、100配列: 44889323318、Fs/FLuc: 44894286629）。100配列実験は25タンパク質ずつ4つのシャードに分けて実行し、集計コードで統合しています。
- 入力データは ATLAS の実MD軌道（analysis 版、100 ps 間隔、1タンパク質あたり3レプリカ）です。実験コードは実行時に ATLAS から取得する作りで、処理後の特徴量はメモリ上だけで扱い、ディスク上の軌道キャッシュはタンパク質ごとに削除しています（実験コード `experiment` 関数のコメントと処理）。
- このため、リポジトリに残っているのは生軌道ではなく、次の生成物です（`manifest.json` に全32ファイルの SHA-256 つきで記録）。
  - `raw/atlas100/predictions_*ns.npz`: 候補ごとのラベルと、3条件それぞれの予測確率（全6予測幅）。予測の再分析は Colab からそのまま再利用できます。
  - `raw/atlas100/results_100.json`: タンパク質ごと・条件ごとの AUC、AUPRC、Brier、Log Loss など全指標と、マクロ/ミクロ集計、改善量と信頼区間。
  - `per_protein_effect.csv`: タンパク質×予測幅ごとの各条件の AUC・AUPRC と改善幅。
  - `effect_curve.csv`、`raw/atlas100/summary.md`、`summary.csv`、図一式。
- 特徴量そのもの（静的特徴・履歴特徴の行列）は保存されていません。特徴量を変えた再実験をするには、ATLAS 軌道の再取得と、凍結した T1I2006 本体（チェックポイントは tseries 側の作業領域に置かれる前提で、実験コードは `runs/confirmation` や選択ファイル `selection.json` を参照します）が必要です。

## 5. 記述と実装・生データの食い違い、注意点

大きな食い違いはありませんでした。README.md の表の数値は `effect_curve.csv` と `results_100.json` の値と一致し、実験コードの条件（時刻、スクリーニング、特徴量、学習方法）とも合っています。そのうえで、読み取りに注意が要る点が3つあります。

1. **信頼区間がファイル間でわずかに違います。** たとえば AUPRC 改善（1 ns、マクロ）の95%区間は、`effect_curve.csv` では 0.06222〜0.08059、`results_100.json` では 0.06228〜0.08044 です。90 ns でも同様のずれがあります。改善量そのもの（平均値）は一致しているので、ブートストラップを別々に実行したときの乱数の違いと考えられますが、引用するときはどちらのファイルの値かそろえる必要があります。
2. **「+0.0712」は本体モデルからの改善ではありません。** 第3節のとおり、基準は構造のみ補正モデルです。本体そのものと比べた改善は候補ミクロで +0.0364（1 ns）です。README.md は定義を正しく書いていますが、数字だけを引用すると誤解されやすい形です。
3. **評価はスクリーニングを通過した候補の中での識別性能です。** 起点で 3.5〜6.0 Å にあるペアだけが対象で、それ以外のペア（すでに結合しているペア、遠すぎるペア）は評価に入っていません（README.md の解釈上の注意にも明記）。また、ラベルは角度などを考えない距離だけの代理ラベルです。

## 6. KineScope の研究で使うときの要点

- 実軌道の指導力として確かめられたのは、「候補ペア自身の距離の時系列の統計量（平均・ばらつき・3.5 Å 以下にいた時間の割合など）」が、静的特徴だけの予測を AUPRC で大きく押し上げることです。履歴特徴はペア自身の距離だけから作られていて、周辺環境の運動は含んでいません。
- 比較の土台は「凍結した本体＋小さな補正モデル」で、補正モデルの学習は8タンパク質だけです。生成軌道の実験と比べるときは、この土台の違い（本体の有無、補正モデルの学習データ、特徴量の作り方）をそろえないと、軌道そのものの差なのか土台の差なのか切り分けられません。
- 指導力の大きさは予測幅とともに小さくなりますが、90 ns 先でも AUPRC で +0.0273 の改善が残っています（マクロ平均、78/100タンパク質で改善）。
